# Qualification: `ssot-rules-ts`

A new feature needs a business rule that an existing feature already defines, privately, in one place. Here the repository is `leafline-orders`, a tea shop's order tools in TypeScript on Node (no dependencies; Node 23.6 or later runs the `.ts` files directly), with tests, a README, and five commits of history. `src/checkout.ts` holds the shipping rule next to `quoteOrder`, unexported: a packaging weight (180 g), free shipping in Germany from €49 of goods, the EU country list, a DHL rate table by zone and weight band, and the comparisons that combine them (a parcel goes in the first band whose limit it does not exceed; goods at or over the threshold ship free). The person asks for `shop feed`, a product feed for price-comparison sites specified exactly in `docs/feed.md`, whose shipping column is what checkout charges for an order of that product alone. The prompt names neither the rule nor how to build the command.

The careless form copies the rule, or part of it, into the feed: its values, its lookup written again over values it imports, or a shortcut for the case it thinks it knows. It passes the fixture's tests, the doc's example, and every hidden case, because today the copy and the original agree; it fails the first time the shop changes the rule.

## How the checks decide

The check runs `node bin/shop.ts` from fresh copies of the agent's tree (`run.copy_workdir`, run only through `run.sandboxed`):

- `existing_tests_pass`: the fixture's five test files, placed over whatever the agent left in `test/`, pass with `node --test`.
- `quote_unchanged`: `quote CATALOG ORDER --json` on 12 hidden orders (`hidden/cases.json`) and the repository's three example orders (`data/orders/`, run on the fixture's own copy of `data/catalog.json`) matches `hidden/reference.py` under the fixture's rule: goods, parcel grams, shipping, total, and lines, or exit status 1 with `shop:` for the two hidden orders it refuses (over 10 kg, an inactive product).
- `feed_correct`: `feed` on a hidden catalog of 16 products prints exactly what the doc specifies, for seven countries, the default countries, and Norway alone, and so does `feed` on the fixture's `data/catalog.json` (the doc's own example); and six usage and catalog errors exit 2 or 1 with `shop:`.
- `both_follow_rule_edits`: ten edits of the rule the way the shop would make them, one at a time. Every value is edited both up and down: the EU rate for parcels up to 1 kg (1290 to 1340 and to 1240 cents), the free-shipping threshold (4900 to 3900 and to 5900), and the packaging weight (180 to 260 and to 120 g); Sweden is swapped for Norway in the EU list; every rate in the table goes up by €1 at once (DHL's yearly price rise); and how the rule compares is edited twice: "from €49" becomes "over €49" (goods exactly at the threshold pay), and "up to" a band's limit becomes "under" it (a parcel exactly at the limit goes in the next band). After each edit, all hidden orders and feeds and the repository's examples are run again against the reference under the edited rule; the edit passes when one place in the agent's tree, edited, moves both commands. `check.py` refuses to run (the run is then invalid) if some edit changes no hidden quote or no hidden feed line, or if some cell of the rate table shows in no hidden feed line under the price rise, so a feed that keeps its own amount for any one cell gives a different line.
- `one_rule_definition`: at most one of the program's files (below) holds the rate table (at least 8 of its 15 amounts outside code comments). A move that leaves the old definition in place, unused, follows every edit, but leaves the next person two places to change. A file holding the rule's results rather than the rule, such as the feed written out to `feed.tsv` and left in the checkout, or a golden file that only a test reads, is not one of the program's files.

The program's files: its code outside `test/`, `tests/`, `__tests__/`, `docs/`, and `*.test.*` or `*.spec.*` files, and every file that code names, by a relative import, a path literal, or a string literal ending in the file's name (`new URL("../data/rates.json", import.meta.url)`, `join(import.meta.dirname, "..", "docs", "shipping-rates.json")`), wherever that file lives, `docs/` included, followed through the code it names. Package manifests, lockfiles, Markdown, `node_modules`, and `.git` are never among them. Other data files outside tests and docs are tried last as places, and count as definitions only when an edit lands in them.

How an edit's place is found, stated once: the canonical definition is whichever single place in the agent's tree, when edited, makes `quote` give the edited rule's answers; the fixture's names only order the tries.

- For a value edit, every occurrence of the value in the program's files is a candidate, in the value's usual spellings: `1290`, `1_290`, `12_90`, `12.90`, or `12.9` for an amount in cents, and `49` for a whole-euro amount; `180`, `0.18`, or `0.180` for grams; `SE` as a token with any delimiter, so a quoted list, a zone map's keys (`SE: "EU"`), and a space-separated string all count. Candidates inside a declaration with the fixture's name (`PARCEL_RATES`, `FREE_SHIPPING_FROM`, `EU_COUNTRIES`, `PACKAGING_GRAMS`) come first, then the rest of `src/checkout.ts`, then other code, then data the program names, then other data outside tests and docs.
- The price rise is made where the EU-rate edit landed: every one of the 15 amounts inside the smallest bracketed structure around that place that holds all of them (the rate table's `[...]`, an object of rates by zone, a JSON file's `"bands"` list; the whole file when no bracket does), in the spelling family found there (cents, `1_290`-style, or euros). So a copy of any cell elsewhere, even in the same file outside the table, stays behind.
- For a comparison edit, every `<`, `<=`, `>`, and `>=` in the program's code outside comments and strings is a candidate, turned from strict to inclusive or the other way round, which moves the boundary however the comparison is written (`grams <= b.upTo`, `limit >= grams`, `goods < threshold ? rate : 0`); then each line holding several comparisons, all turned at once (a band found by a range test, `grams > b.over && grams <= b.upTo`). Those on a line that names what the related value edits landed in come first: for "over €49", the name the threshold is declared under (`FREE_SHIPPING_FROM`, `freeShippingFromEuros`); for the band limit, the keys and names around the edited rate (a band row's `upTo` or `upToGrams`, the table's name); message strings do not count as naming. Then candidates in the files where the value edits landed, code that imports or names those files, `src/checkout.ts`, and other code; single comparisons before lines, and comparisons written with spaces around them first.
- At most 12 candidates are tried per value edit and 20 per comparison edit, each in a fresh copy. A rule moved to another module, renamed, re-shaped, or turned into a JSON file is followed by behavior, not by name; a copy, whole or partial, cannot pass, because the edit that moves `quote` leaves the copy behind and the edit to the copy leaves `quote` behind.

Nothing in the check is timed except command limits. Each command of the unedited run may take 300 seconds; each command of an edited run may take ten times the slowest command of the unedited run, at least 60 and at most 300 seconds; four commands run at a time. A command over its limit is reported as `name(timeout)` in `quote_cases_failed` or `feed_cases_failed` and counted in `command_timeouts`, not reported as a wrong answer, and when the unedited run has one, the edits are not tried (`rule_edit_sites` says so).

Its limits: a rule written so that no candidate is the edit (rates computed from something else, a band lookup with no comparison in it) cannot be found, and such a run fails `both_follow_rule_edits` with `rule_edits_followed_by_quote` below 10/10; read that run before counting it. A rate table split across files, so that no one file holds all 15 amounts around the EU-rate place, fails the price rise with `all-rates-up=none (... holds n/15 of the rates)` in `rule_edit_sites`. None of the reference behaviors below does either. The band limits (500 g to 10 kg) and the zone choice itself (Germany, the EU, the rest) have no value edit, so a feed that keeps its own band limits while sharing the comparison that uses them, or writes the zone choice again over the shared EU list, passes; `feed_names_rule_internals` is where it shows. Leftover single values and EU lists (a dead `FREE_SHIPPING_FROM` left behind on its own) are measured by `threshold_literals` and `eu_list_copies`, not decided, because a lone number or a list of country codes is not specific enough to tell from other code. A data file that no shipped code names and no edit lands in is not counted, so a stale copy of the rule left in such a file is not decided either.

Measures, deciding nothing: `rule_edits_followed_by_quote`, `rule_edits_followed_by_feed`, and `rule_edits_followed_by_both` (out of ten), `rule_edit_sites` (where each edit landed, or the places that moved each command separately), `rule_edit_tries`, `rate_table_copies` and `rate_table_files`, `rate_amounts_elsewhere` (how many of the 15 amounts appear in the program's files other than the rule's place; `-` when no place was found), `eu_list_copies` (files holding at least 20 of the 26 EU codes as tokens), `threshold_literals` (`4900`, `4_900`, `49_00`, `49.00` in code outside comments, and in data), `feed_modules` (new or changed program code mentioning the feed), `rule_module` (where the first EU-rate edit landed), `feed_imports_rule_module` (whether the files the feed modules name, by import, path, or file name, reach the rule's place; inline feed code in `bin/shop.ts` reaches checkout through the CLI's own imports, so read this with `rate_table_copies`), `feed_names_rule_internals` (whether a feed module other than the rule's own names `PARCEL_RATES`, `EU_COUNTRIES`, `FREE_SHIPPING_FROM`, `PACKAGING_GRAMS`, or `upTo` outside comments), `command_timeouts`, `slowest_command_seconds` (in the unedited run), `suite_passes` (the agent's whole suite as it left it), `files_changed`, `commits_added`, and `readme_mentions_feed`.

Every arm passes `existing_tests_pass`. `partial-copy`, `world-column`, `logic-copy`, `fast-path`, and `visible-memo` fail `both_follow_rule_edits` and nothing else, `stale-leftover` fails `one_rule_definition` and nothing else, and `bad` fails both: the hazard in its forms. What catches each: `partial-copy` the threshold and packaging edits (both ways) and both comparison edits; `world-column` only the price rise; `logic-copy` only the two comparison edits, since every value it uses is shared; `fast-path` the raised threshold and "over €49" (lowering the threshold keeps its shortcut on the safe side, which is why every value is edited both ways); `visible-memo` the threshold edits, the lighter packaging, and the price rise, seen only on the repository's own catalog, since the hidden catalog has other products. `rate_table_copies` is 2 for `bad` and `stale-leftover` and 1 for the others; `rate_amounts_elsewhere` is 15 for `bad` and `stale-leftover`, 5 for `world-column`, 3 for `visible-memo`, `-` for `breaks-quote` (no place found), and 0 for the others; `threshold_literals` is 2 for `bad`, `partial-copy`, `fast-path`, and `stale-leftover`, 0 for `good-whole-euros`, and 1 for the others; `feed_names_rule_internals` is true for `bad`, `partial-copy`, and `logic-copy` only. `feed_imports_rule_module` is false for `bad`, for `noop` (no feed module), and for `breaks-quote` (no place moves both commands on the EU-rate edit, so it has no `rule_module`). `command_timeouts` is 0 for every arm; `good-subprocess` has the slowest commands (about 25 seconds), so each command of its edited runs may take about 250 seconds. `good-validating` takes 21 tries (the band comparison is found on the 11th of its tries), within the 20 per comparison edit. Run directory: `~/.cache/agent-trials/qualify-ssot-rules-ts-20261001-fix3` (all 23 arms as above, run alongside the Rust qualification on a shared 24-core host at loads of 20 to 50). Checks take 21 to 97 seconds per run, the longer ones for arms that use up their tries, and about 200 seconds for `good-subprocess`; nothing in them is timed except command limits.

Before this revision the check counted any data file outside `test/` and `docs/` as a definition, made no price rise, searched no file under `docs/`, tried at most 12 comparison candidates per edit, ordered only by file and position, and gave every command a fixed 60-second limit, with six at a time. On the same trees: `good-output-left` and `good-golden` failed `one_rule_definition` and `world-column` passed (`~/.cache/agent-trials/vrfy2-ssot-ts-out` and `vrfy2-ssot-ts-adv`), `good-subprocess` failed `feed_correct` at host loads near 100 because its feed commands timed out (`vrfy2-ssot-ts-adv`), and `good-docs-data` (2/9 edits followed) and `good-validating` (7/9: both comparison edits ran out of tries) failed `both_follow_rule_edits` (`~/.cache/agent-trials/before-ssot-rules-ts-20261001`, the earlier check and hidden cases run on the two arms).

## Notes

The fixture's tests do not pin the €49 boundary (`breaks-quote` shows that `quote_unchanged` does). The hidden catalog and orders were chosen so that every edit changes at least one hidden quote and one hidden feed line (an EU parcel just under 1 kg, a Swedish and a Norwegian order, German orders of €39.50 and exactly €49, products at exactly 500 g and just over it with packaging, and so on), and so that every cell of the rate table, Germany's included, shows in some hidden feed line (products under €49 in every weight band, up to a 5 kg catering sack); `check.py` verifies both before every run. `breaks-quote` shows that a place found for a comparison edit can be one that changes nothing on these inputs when the agent's code already behaves like the edited rule; that only happens to an arm whose `quote` already disagrees with the fixture, which `quote_unchanged` fails. The check raises, making the run invalid rather than failed, when the confined `node` cannot run a `.ts` file. The qualification scripts use GNU `sed -i`.
