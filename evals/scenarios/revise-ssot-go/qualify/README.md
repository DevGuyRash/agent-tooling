# Qualification: `revise-ssot-go`

A change to a business rule that earlier changes already copied, with the copies drifted. The repository is `permitctl`, a borough council's resident parking permit tool in Go (standard library only), with tests, a README, and six commits of history. Three commands charge for a permit:

- `quote` (the website's application form, `internal/quote`, where the rule was first written);
- `renewals` (the monthly renewal letters, `internal/renewals`, a copy written as a `switch`);
- `forecast` (finance's income forecast, `internal/forecast`, a copy whose band comparison came out exclusive).

The rule is a charge by CO2 band, where a vehicle exactly on a band's upper figure is in that band, plus a diesel surcharge and a surcharge for the second and later permits at an address. Two later charge changes each reached only some copies, so today each copy is wrong in a different part. The quote charges 50.00 for later permits, the letters charge band C at 90.00, and the forecast puts a vehicle exactly on 100, 120, 150, 185, or 225 g/km in the next band. `docs/permit-charges.md` says 60.00, 96.00, and that band. The history shows each slip (`git log -p internal docs`).

The request is next year's change, which Priya already wrote into `docs/permit-charges.md`: a new band G over 255 g/km at 292.00 (band F now stops at 255), and the diesel surcharge 45.00 instead of 30.00. It is to be used by the quote, the renewal letters, and the forecast. The prompt asks for that and nothing more: it names neither the copies, nor that they disagree, nor how to fix them. The charges page says permitctl uses it for everything it works out, so moving onto the charges includes the parts each copy has wrong. Editing all three copies, and fixing each one's drift, passes the visible tests and every hidden case today, and leaves next year's change to be made three times.

## How the checks decide

The check copies the agent's tree without following links (`_shared/no_interpreter.py`), builds `go build -o permitctl ./cmd/permitctl` offline in bubblewrap (where the README's `go build ./cmd/permitctl` leaves it), and runs the program from the repository's root, read-only. The exports are written from `hidden/cases.json` (made by `hidden/make_cases.py`) to a directory outside everything a build can see, and bound in only when the program runs. Results are compared with `hidden/reference.py`, which prints what the fixture prints under any rule passed in. Run under each fixture copy's own old rule, it matches the fixture binary's actual output on all 57 hidden cases. Expected output comes from the reference at check time.

- `builds`: the build succeeds.
- `existing_tests_pass`: the fixture's tests that the request does not touch (`internal/money`, `internal/permits`, and `cmd/permitctl/main_test.go`, with their `testdata/`) are placed over the agent's tree with every other test file removed, and pass when run by name. The fixture's quote, renewals, and forecast tests pin the old charges, so updating them is part of the request, and they are not among these.
- `existing_behavior_kept`: 25 hidden cases of behavior the request does not touch give what the fixture gives. They cover an export with a byte-order mark and Windows line endings (as the permit system writes it), columns in another order with values padded and fuel and registration in any case, a month with no renewals, refusals with exit status 1 and `permitctl:` (a missing file or column, a bad g/km figure, fuel, household number, or date, an empty file), and bad command lines with exit status 2.
- `new_policy_charged`: 18 hidden cases where the fixture's three copies, each with the request applied, would agree (no later permits, no band C, no vehicle exactly on a band figure, 255 included). Each command prints exactly what `docs/permit-charges.md` gives, band G and the 45.00 surcharge included.
- `drift_resolved`: 14 hidden cases where those copies disagree, covering later permits, band C, and vehicles exactly on 100, 120, 150, 185, 225, and 255 g/km, through every command. Each command prints what `docs/permit-charges.md` gives.
- `all_follow_rule_edits`: after the agent's change, the rule is edited again twelve ways, one at a time, the way the council would edit it next year. These are band C up and down (96.00 to 99.00 and to 93.00), band G up (292.00 to 310.00), the diesel surcharge up and down (45.00 to 50.00 and to 40.00), the later-permit surcharge up and down (60.00 to 65.00 and to 55.00), band D's figure down (185 to 180), and band F's up (255 to 260). Then every band charge goes up by 4.00 at once, "a vehicle exactly on a band's upper figure is in that band" becomes "in the next band", and "the second and every later permit at the same address pays 60.00 more" becomes "the third and every later permit", an edit of how the parts of the charge combine. Under that last edit the quote for a second permit shows no surcharge line, as the fixture's quote shows the line only when the surcharge applies, and the letters' ", second permit" note may either keep describing the permit, as the fixture's does, or follow the surcharge; both are accepted. After each edit, every policy and drift case is run again against the reference under the edited rule. An edit passes when one place in the agent's tree, edited and rebuilt, makes the quote, the letters, and the forecast all give the edited rule's answers. A copy of any value, of the band comparison, or of the later-permit condition fails. The last edit is what catches a partial consolidation that shares the bands, the band lookup, and the surcharge amounts, and leaves each command to add the surcharges itself (`surcharge-copy`). Band labels in the quote ("151 to 185 g/km") come from the figures, as the fixture computes them, so a design that writes a figure again in a label string cannot follow the figure edits. Before every run, `check.py` verifies that each policy case is one the copies agree on and each drift case one they disagree on. It also verifies that every edit changes some hidden output of every command, and that every band's charge shows in some output of every command under the price rise. If any of that fails, it refuses to run, and the run is invalid.
- `one_rule_definition`: at most one of the program's files holds the band charges, meaning at least 3 of the charges for bands A, B, D, E, and F outside comments. Neither the request nor the drift touches those charges, so an old copy left behind unused still carries them.

The program's files are the Go outside `*_test.go`, `testdata/`, `docs/`, and `vendor/`, plus every file that code names by a string literal ending in the file's name or by a `//go:embed` pattern, wherever it lives, followed through. `go.mod` is never among them. A document such as `docs/permit-charges.md` counts as a definition only when an edit lands in it, so code that merely mentions the page (`good`'s `const Source = "docs/permit-charges.md"`) does not make it a second table. Other data files outside tests and docs are tried last as places, and count as definitions only when an edit lands in them.

How an edit's place is found. The canonical home is wherever one edit moves every command. The fixture's names only order the tries.

- For a value edit, every occurrence of the value in the program's files is a candidate, in its usual spellings. A charge in pence can be `9600`, `9_600`, `96_00`, `96.00`, `96.0`, or `96`; band figures are `185` and `255`. Candidates come in this order: inside a declaration with one of the fixture's names for that part (`bands`; `dieselSurcharge`, `diesel`; `extraPermit`), then in files where an earlier edit landed, then other Go, then data the program names, then other data.
- The price rise is made where the first band C edit landed. It edits every band charge in the smallest bracketed structure around that place that holds all seven (the bands slice, a JSON array, a `switch`'s braces), or the whole file when none does, in the spelling found there. It edits each spelling once.
- For the band comparison edit, every `<`, `<=`, `>`, and `>=` in the program's Go outside comments and strings is a candidate, turned between strict and inclusive. Then each line holding several comparisons is tried with all of them turned at once. Then each group of comparisons with the same left side in one block is tried, all turned at once; this covers the cases of a `switch` such as `case co2 <= topA:` ... `case co2 <= topF:`. Candidates on a line that names what the figure edits landed in come first, then candidates in files where the value edits landed, then code that imports or names those files, then other code.
- For the combination edit, every comparison of something with 1 or 2 in the program's Go outside comments and strings that can say "a later permit" or "the first permit" is a candidate, moved on by one permit: `> 1` becomes `> 2`, `>= 2` becomes `>= 3`, `!= 1` becomes `> 2`, `== 1` becomes `<= 2`, `<= 1` becomes `<= 2`, `< 2` becomes `< 3`, and the same written the other way round (`1 < household`). Candidates on a line naming the household (or what the later-permit edits landed in) come first, then the files as for the comparison edit. The hidden drift inputs hold second and third permits, so dropping the surcharge altogether is told apart from starting it at the third.
- At most 12 candidates are tried per value edit and 24 per comparison or combination edit. Each one is edited in the check's copy, rebuilt (the build cache is shared, so a rebuild takes about a second), run, and restored. A rule moved to a new package, kept in `internal/quote` and exported, turned into an embedded JSON file, or written as a `switch` over named figures is followed by behavior. A copy cannot pass, because no single edit moves all three commands.

An edit is followed only when every case is right under it, so a tree that is wrong before any edit (`wrong`, `wrong-drift`, `copies-drift-kept`) follows none. Read `new_policy_charged` and `drift_resolved` first. The exception is a tree that already behaves like an edited rule. `wrong-drift` already compares exclusively, so a toggle that changes nothing on these inputs counts as its place for the comparison edit, and it shows 1/12. `copies-drift-kept` shows the same for its forecast alone, and its quote follows the combination edit through its own copy, because its drifted later-permit charge stops showing once the surcharge starts at the third permit: 1/12 each in `rule_edits_followed_by_forecast` and `_quote`, 0/12 for all three. Both fail `drift_resolved`. Each command run may take 30 seconds and each build 600 seconds; nothing else is timed.

Its limits:

- Some rules cannot be found by any candidate, and such a run fails `all_follow_rule_edits` with `rule_edits_followed_by_quote` below 12/12; read that run before counting it. Examples are charges computed from something else, band figures held as offsets from one another, and bands held by the figure they start at (`{"D", 151, 14200}` with `co2 >= b.From`, scanned from the top, the `lower-bounds` arm, correct on every hidden case), which the band-figure edits, looking for 185 and 255, and the comparison edit cannot reach, so it follows 9/12.
- With positional struct literals (`{"D", 185, 14200}`) no field name is bound to the figure, so comparison candidates are ordered by file rather than by name. The good arms below find theirs within 3 tries.
- The diesel condition on its own has no edit: a design that shares the later-permit condition but has each command add the diesel surcharge itself passes. The later-permit condition copied, with or without the diesel one, fails the combination edit.
- The fuel list and the band names have no edit.
- A data file that no shipped code names and no edit lands in is not counted.

Measures, deciding nothing:

- `rule_edits_followed_by_quote`, `_renewals`, `_forecast`, and `_all` (out of 12).
- `rule_edit_sites`: where each edit landed, or the places that moved each command separately.
- `rule_edit_builds`.
- `table_copies` and `table_files`.
- `rule_module`: where the band C edit landed, or `-` when no place moved the quote.
- `charges_elsewhere`: band charges found in the program's files other than the rule's place.
- `consumers_reach_rule_module`: whether the quote, renewals, and forecast packages reach the rule's file through imports and named files.
- `policy_cases_failed`, `drift_cases_failed`, `existing_cases_failed`, and `build_log_tail`.
- `fixture_tests` and `fixture_tests_output`.
- `suite_passes`: the agent's whole `go test ./...` as it left it.
- `test_files_changed`, `docs_charges_changed`, `files_changed`, and `commits_added`.

Checks take 45 to 123 seconds per run on a host shared with other trials (load average about 45 on 24 CPUs); the copies use up their tries with a rebuild each. Run directory: `~/.cache/agent-trials/ssotfix-qualify-revise-ssot-go` (15 arms as above).

## Notes

The fixture's tests never cover the drifted inputs, which is how the drift went unnoticed. The hidden inputs were made so that every edit changes at least one output of every command. Examples are vehicles at 183 g/km (band D, band E once D stops at 180), 256 to 260 g/km (band G, band F once F reaches 260), every band figure exactly, second permits (a quote with `-second`, and second permits in each month's letters and in the forecast) and a third, and every band in each month's letters and in the forecast. `check.py` verifies that before every run. With the request applied to the forecast's exclusive copy, 255 g/km becomes one of its slips, so the 255 g/km inputs are drift cases. The check raises, making the run invalid rather than failed, when bubblewrap or the host's Go is missing. The qualification scripts lay files over the tree with `cp -R`.
