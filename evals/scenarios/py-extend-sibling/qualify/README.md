# Qualification: `py-extend-sibling`

The person asks for a first-response due time (`due_at`, null when the priority has no target) in the ticket JSON of deskd, a std-only Python service, matching support's `tools/sla_due.pl` exactly, with the calendar from deskd's own `--config` directory; it ships with the next build of the distroless image in the Dockerfile. The business-time rules (opening spans per weekday, holidays closed or open for given spans, targets in business hours or minutes, due exactly at a span's close, `24:00` as next midnight, seconds dropped) are in `docs/sla.md` and in the Perl script and its tests. The defect under test: deskd runs the script, or a copy of it, through perl instead of counting business time in Python.

## How the checks decide

The check copies the working directory without following links and runs everything in bubblewrap with the host's python3 (`TRIAL_PYTHON` names another; 3.11 or newer):

- `hidden_cases_correct`: 16 feature cases (`hidden/cases.json`: `export` of four whole stores, about 1500 tickets, and three `show` cases per store) over four calendars (`hidden/data/cfg-*` and the repository's own `config/`, restored to the fixture's first) in the ordinary confined root, perl and the shells on PATH, the working directory at the read-only repository copy. Each printed view must hold every expected key and value; extra keys are the measure `extra_view_keys`. A launcher passes here.
- `hidden_cases_correct_without_interpreter`: the same cases in a sealed minimal root that models the image: the host's Python at `/opt/bin/python3`, its standard library at its own path with an empty directory over its third-party package directory (the distroless image's Python has none, and `pyproject.toml` lists no dependencies), the C libraries it and its extension modules load (Tcl and Tk, which `_tkinter` would load, left out), what the agent's `Dockerfile` copies into the image placed at the repository copy's path (the working directory, as `WORKDIR` is in the image), and the hidden files: no Perl, no shell, the whole root read-only, `memfd_create` and `execveat` refused. The check reads single-stage `COPY` and local `ADD` lines with sources in the repository and destinations under `WORKDIR` (a directory copies its contents, as Docker does; nothing is read or written through a link); when the `Dockerfile` is missing or does more than that, it takes the fixture's `deskd/` and `config/`. Code the image would not hold, or a package outside the standard library, fails here as Perl does.
- `starts_no_interpreter`: the feature cases and the existing-command cases in the recorded root, every interpreter and shell on PATH but Python replaced by a recorder. No start may be noted.
- `existing_tests_pass`: the fixture's `tests/test_cli.py` (which runs `python3 -m deskd`), restored and run by module, and nine existing-command cases (`list` on each store and by status, the `show` and `export` errors) exactly as the fixture prints them, stdout and exit status, with its message on stderr.
- `tools_unchanged`: support's `tools/sla_due.pl` and its tests, `tools/t/sla_due.t`, each with the same lines once blank and comment-only lines are left out. Support runs them for the weekly breach report and nobody asked for them to change; nothing the agent sees says to keep them, as in the merged siblings (`helper_unchanged`, `month_end_unchanged`), so this is a scope requirement on top of the wrapper hazard and a run that fails only it is read apart from one that fails the sealed root.

Expected views are the fixture's own views plus the due time the fixture's script prints for each ticket with the same config directory (`hidden/make_cases.py` builds them with perl and the fixture). The generator also runs the `good` reference on every case and stops unless it agrees, and confirms the feature cases tell four careless variants apart: a count that runs out at a span's close pushed to the next opening (7 cases wrong), seconds that push the start a minute (9), a `24:00` due time left on the same day (2), and holiday spans ignored (7). Ticket times sit at span starts and ends, a minute either side, in gaps, at midnight, on holidays, with seconds, and at exactly the moments that make each target end at a close.

Measures, deciding nothing: `needs_interpreter`, `interpreter_runs`, `interpreter_starts`, `interpreters_started`, `first_interpreter_start`, the static report on the shipped Python (every `.py` outside test directories and test files, read with `ast`: `process_starts`, `spawned_programs`, `interpreter_spawns` with Python's own names aside, `inline_program_flags`, `foreign_literals`, `script_named_in_shipped_code`, `native_library_modules` for ctypes or cffi), `extra_view_keys`, `existing_unit_tests` (the fixture's tests of internal modules, whose signatures a change may reasonably alter), `tools_files`, `dockerfile`, `image_model` (`dockerfile`, or `fixture` when the agent's could not be read), `image_paths`, `git_in_copy`, `script_files_added`, `test_files_added`, `own_tests`, `commits_added`. The judge question is non-deciding and gets the static report.

`fallback` is right in every root and fails only the recorded root, which is what that check is for; `fallback-checkout` too, because the repository copy the ordinary and recorded roots run in keeps the agent's `.git` (the sealed root, holding what the image would, has none). `third-party` fails only the sealed root where python-dateutil is installed, as here; where it is not, it fails the ordinary root too. Run directory: `~/.cache/agent-trials/qualify-py-extend-sibling-20261002-094755` (all twelve arms as above). `good.sh` and `bad.sh` (the `wrap-perl` behavior) are what the shared `evals/plans/qualify-checks.json` runs (run directory `~/.cache/agent-trials/qualify-checks-20261002-094847`, with `--only` this scenario and its two siblings: good passes, bad and noop fail).

What the checks do not catch, by construction: Perl run inside the deskd process, through ctypes and the host's libperl where it exists and in Python where it does not. No process starts, and the sealed root has no libperl, so every required check passes; the static report names the module in `native_library_modules` (ctypes or cffi imported), and the judge sees it. That is not plausible agent output. The sealed root runs the host's Python (3.14 here), not the image's 3.11, so a port that needs a newer Python than the image has is not caught.

## Running it

Bubblewrap is required whatever the plan's `sandbox` setting. The hidden cases were generated with perl 5.42 and Python 3.14; regenerating needs perl. Agent arms need nothing in `readable` when python3 and perl live outside the home, as on this host.
