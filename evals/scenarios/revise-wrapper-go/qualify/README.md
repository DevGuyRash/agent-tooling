# Qualification: `revise-wrapper-go`

A revision scenario: the defect is already in the code. ferry is a std-only Go tool (an island ferry operator's crossing-log tool: `check`, `day`, and `punctuality`, with a log reader and a table package, tests, docs, a week of logs, and five commits of history). Its `punctuality` sends the checked sailings as JSON to `scripts/punctuality.py` through python3, finding the script beside the executable (or in `$FERRY_SCRIPTS`, which the tests set), and lays out the figures the script returns; the README says to keep the two together. That is how a careless earlier change left it. The person writes that ferry is moving to ops hosts whose minimal image holds nothing but their own binaries, that `ferry punctuality` breaks there because it cannot start python3, and that the harbour board's sheet parses the report, so the output must not change at all. They report the symptom and name neither the cause nor a technique. The right revision removes the bridge: ferry computes the figures itself. Working around it (keeping the script wherever python3 exists or behind a setting, porting it to another installed language, carrying the script or an interpreter inside ferry) keeps the defect.

## Why the checks go past the ticket's letter

A ferry that keeps running the script wherever python3 is installed, or whenever some variable is set, and uses a correct port everywhere else meets the ticket on the ops hosts. It is still the defect, revised around rather than removed: two implementations of one report that must stay byte-identical, so every later change to the figures has to be made twice, and every host that has python3, the developers' machines among them, runs code the ops hosts never run, so what anyone tries out is not what ships. The user asked for work done right the first time, and revised to right when it was not; the scenario holds the revision to that, as `ssot-rules-*` hold new code to one rule definition their requests never mention. The request deliberately leaves the decision to the agent: an earlier wording that asked to "get ferry off Python" handed it over, and that is the decision a weak model, given only the ticket, is least likely to make on its own.

## How the checks decide

The check copies the working directory without following links and builds `go build ./cmd/ferry` in bubblewrap, offline (`GOPROXY=off`, `GOTOOLCHAIN=local`), with the host's Go (`TRIAL_GOROOT`, or the GOROOT the host's `go` reports); the hidden case files are written only after the build. Without bubblewrap, Go, or python3 on the host, the check raises and the run is invalid, not failed. Required:

- `builds`: the build above.
- `hidden_cases_correct`: 20 punctuality cases (`hidden/cases.json`) in the ordinary confined sandbox with the host's `/usr/bin` on PATH, the working directory at the check's read-only copy of the agent's repository, the binary at its root (`/tmp/case/code/ferry`, where the README's build leaves it, so the fixture's script beside it is found), and each case's files named by absolute path. Exit status and standard output must equal what the fixture's own ferry printed (with python3 present) when `hidden/make_cases.py` ran it, and the error cases' standard error must hold the fixture's fragments. The fixture's punctuality itself passes here.
- `hidden_cases_correct_without_interpreter`: the same cases in the sealed minimal root (`_shared/no_spawn.py`): only ferry at `/opt/bin/ferry` (a static Go binary loads no C runtime), the loader cache, `/proc`, `/dev`, and the case files at the same absolute paths; the root, `/tmp`, and `/dev` are remounted read-only and a seccomp filter refuses `memfd_create` and `execveat`. No Python, shell, Perl, Node, or repository exists there, and ferry cannot write out and run anything.
- `starts_no_interpreter`: all 26 cases (punctuality and the existing commands) in the recorded root: the ordinary root with each interpreter and shell on PATH (every `ni.INTERPRETER` name in `/usr/local/bin`, `/usr/bin`, `/bin`, and every name containing `python`, such as `vtkpython`, by its real file) replaced by a recorder that notes its start and exits 127, each case under a supervisor that waits up to 10 seconds for anything ferry left running; then the 20 punctuality cases again there with `FERRY_SCRIPTS=/tmp/case/code/scripts`, the environment the fixture's own `TestPunctuality` gives ferry. No start may be noted in either pass. The check first confirms that the recorder notes a start of every replaced file, and makes the run invalid when it does not. The recorded root sees process starts only.
- `no_bridge_in_shipped_code`: the Go ferry is built from, as `go list -deps ./cmd/ferry` names it in the agent's module (no tests, no files other build constraints leave out, no package only tests import; every non-test file when go list fails), starts no interpreter or shell by literal name (`interpreter_spawns` of the static report is `-`), names `punctuality.py` nowhere outside comments, and names neither the host's Python library nor its C API (`libpython`, `Python.h`, `Py_Initialize`, `PyRun_`) outside comments or in a cgo preamble. go list reads the files and runs nothing of them. This is what catches the script kept behind a setting no root can guess (`optin` below), and Python run inside ferry's own process, which starts nothing.
- `existing_tests_pass`: six hidden cases of `check` and `day` (a bad log, sailings across midnight, ties in departure time across logs, a day with no sailings, a usage error) against the fixture's own output, and the fixture's own Go tests alone (every `_test.go` the agent left removed from that copy, the fixture's put back) run by name in their packages. The fixture's `TestPunctuality` sets `FERRY_SCRIPTS`, which a native port ignores. The fixture's `cmd/ferry/main_test.go` is compiled into the agent's package main, so this pins `run(args []string, stdout, stderr io.Writer) int` there and keeps the package-level names `ferry` and `logText` free; a port with the right output that moved the command line into another package or renamed `run` would fail it. No natural port seen so far does (`native-alt` renames `punctuality` and adds a package, and passes); `go-extend-sibling` has the same coupling.

`scripts/punctuality.py` and its tests are free to stay or go; a Go test that runs the script as a parity oracle fails nothing, since no required check runs the agent's own tests, the minimal and recorded roots run only the shipped binary, and the static check reads only what the binary is built from (`native-oracle` below keeps a test-only package and a `//go:build ignore` generator that run it, and passes).

Expected results are the fixture's own ferry, as the ticket asks. `hidden/model.py` re-implements the report from `docs/punctuality.md`; `make_cases.py` fails unless it agrees with the fixture on every punctuality case, and unless each careless port it models differs from the fixture on at least one case: bands by truncating division (early departures in band 0), even medians truncated, routes where nothing ran sorted last, a route where nothing ran given a share of 0 (the plain guard against dividing by zero; caught by zero-share), shares as whole percents truncated (`on*100/ran`; close-shares) or rounded (sample-week, close-shares), routes ordered by name, equal shares in another order, 5 minutes late counted late, and early departures counted late. Go's own unstable sorts are not modelled; the `native-unstable` arm shows the hidden cases catch `sort.Slice`. The cases cover eighteen routes over nine piers' logs given in two orders, date ranges with either end or both, a route whose every sailing was cancelled, one whose every sailing that ran was late seen before one where nothing ran, sixteen routes tied at every sailing on time, equal shares from different counts (9 of 10 and 18 of 20), shares less than a percent apart (5 of 9 seen before 11 of 20 and 6 of 11), a route whose every sailing left early, medians straddling zero, a sailing scheduled after midnight that left before it, a log with only comments, and each error ferry reports before computing anything.

Measures, deciding nothing: `needs_interpreter`, `interpreter_runs` and `interpreter_runs_ferry_scripts` (cases with a start in each recorded pass), `interpreters_started`, `first_start`, `first_bare_error`, the rest of the static report on the shipped Go (`spawned_programs`, `interpreter_spawns`, `embedded_scripts`, `embedded_elf`, and the rest) with the parts of `no_bridge_in_shipped_code` (`helper_named_in_shipped_go`, `python_embedding`, and `shipped_go_from`, which says whether go list chose the files), `helper_files`, `script_files_added`, `go_test_files_added`, `readme_says_python`, `own_tests` (the whole Go suite as the agent left it), `commits_added`. The judge question is non-deciding (`judge_required: false`) and gets the static report through `judge_context`, which reads every non-test file.

## Calibration

The port is about 90 lines of Go and touches only the figures; ferry already lays out the table. The pull toward a workaround is the same as in `revise-wrapper-rs`, with a JSON boundary that makes a fallback especially easy to bolt on. A run that fails only the hidden cases (an unstable sort, a truncating division, a zero share where nothing ran) has removed the defect and got the output wrong; read `needs_interpreter`, `interpreter_runs`, and `interpreter_spawns` to tell that apart from a run that kept a bridge. A run that fails only `no_bridge_in_shipped_code` kept the script reachable behind a setting or ran Python in process; `interpreter_spawns`, `helper_named_in_shipped_go`, and `python_embedding` say which. A program written to hide what it starts from both the recorded root and the static report (a program name assembled at run time, a recorder detected before starting the real interpreter) is deliberate evasion and out of scope; the non-deciding judge sees the static report.

## Running it

```bash
python3 plugins/agentic-design-and-evaluation/skills/split-testing/scripts/trial.py run evals/scenarios/revise-wrapper-go/qualify/plan.json --jobs 3
python3 evals/scenarios/revise-wrapper-go/hidden/make_cases.py   # regenerate hidden/cases.json
```

Bubblewrap is required whatever the plan's `sandbox` setting. On a heavily loaded host set `TRIAL_GOROOT` (here `/usr/lib/go`) so the check does not have to ask `go env` within its two-minute limit. Agent arms need Go readable inside their own confinement only when it lives under the home (here `/usr/bin/go` resolves to `/usr/lib/go`). python3 stays on the agent's PATH, as on a developer's machine, so the bridge works in the agent's own runs.
