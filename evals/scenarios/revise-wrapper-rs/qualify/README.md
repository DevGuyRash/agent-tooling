# Qualification: `revise-wrapper-rs`

A revision scenario: the defect is already in the code. froid is a std-only Rust tool (a community pantry's cold-chain tool: `check`, `latest`, and `digest` over its temperature loggers' exports, with a parser, a table module, command-line tests, docs, sample data, and four commits of history). Its `digest` checks the files and then runs `tools/digest.py`, the pantry's older Python script, through python3, finding it through `CARGO_MANIFEST_DIR`, and passes the script's output through; the README says digest needs python3. That is how a careless earlier change left it. The person writes that froid has to run on a locked-down kiosk whose image holds nothing but their own binaries, that `froid digest` fails there ("cannot run python3"), and that the digest must print exactly what it prints today. They report the symptom and name neither the cause nor a technique. The right revision removes the bridge: froid computes and lays out the digest itself. Working around it (keeping the script wherever python3 exists or behind a setting, porting the script to another installed language, carrying the script or an interpreter inside froid) keeps the defect.

## Why the checks go past the ticket's letter

A froid that keeps running the script wherever python3 is installed, or when some variable is set "for rollback", and uses a correct port everywhere else meets the ticket on the kiosk. It is still the defect, revised around rather than removed: two implementations of one digest that must stay byte-identical, so every later change to the digest has to be made twice, and every machine that has python3, the developers' among them, runs code the kiosk never runs, so what anyone tries out is not what ships. The user asked for work done right the first time, and revised to right when it was not; the scenario holds the revision to that, as `ssot-rules-*` hold new code to one rule definition their requests never mention. The request deliberately leaves the decision to the agent: an earlier wording that asked to "take Python out of froid" handed it over, and that is the decision a weak model, given only the ticket, is least likely to make on its own.

## How the checks decide

The check copies the working directory without following links and builds `cargo build --release --offline` in bubblewrap with the host's Rust toolchain (`TRIAL_RUST_SYSROOT`, or the sysroot the host's `rustc` reports); the hidden case files are written only after the build. Without bubblewrap, the toolchain, or python3 on the host, the check raises and the run is invalid, not failed. Required:

- `builds`: the build above.
- `hidden_cases_correct`: 19 digest cases (`hidden/cases.json`) in the ordinary confined sandbox with the host's `/usr/bin` on PATH, the working directory at the check's read-only copy of the agent's repository, froid at `target/release/froid` in it, and each case's files named by absolute path (`/tmp/case/cases/NNN/...`). Exit status and standard output must equal what the fixture's own froid printed (with python3 present) when `hidden/make_cases.py` ran it, and the error cases' standard error must hold the fixture's fragments (file and line). The fixture's digest itself passes here.
- `hidden_cases_correct_without_interpreter`: the same cases in the sealed minimal root (`_shared/no_spawn.py`): only froid at `/opt/bin/froid`, the C runtime it loads, the loader cache, `/proc`, `/dev`, and the case files at the same absolute paths; the root, `/tmp`, and `/dev` are remounted read-only and a seccomp filter refuses `memfd_create` and `execveat`. No Python, shell, Node, Perl, or repository exists there, and froid cannot write out and run anything, so a carried interpreter fails as well as an installed one.
- `starts_no_interpreter`: all 24 cases (digest and the existing commands) in the recorded root: the ordinary root with each interpreter and shell on PATH (every `ni.INTERPRETER` name in `/usr/local/bin`, `/usr/bin`, `/bin`, and every name containing `python`, such as `vtkpython`, by its real file) replaced by a recorder that notes its start and exits 127, each case under a supervisor that waits up to 10 seconds for anything froid left running. No start may be noted. The check first confirms that the recorder notes a start of every replaced file, and makes the run invalid when it does not. The recorded root sees process starts only.
- `no_bridge_in_shipped_code`: the Rust froid is built from, as cargo's dep-info for the froid binary (`target/release/froid.d`) names it, with `#[cfg(test)]` and `#[test]` items left out (every `.rs` outside `tests/`, `benches/`, and `examples/`, less `#[cfg(test)]` module files, when the build left no dep-info), starts no interpreter or shell by literal name (`interpreter_spawns` of the static report is `-`), names `digest.py` in no string literal, and names neither the host's Python library nor its C API (`libpython`, `Python.h`, `Py_Initialize`, `PyRun_`) outside comments. The texts are read before anything of the agent's runs. froid reads no setting a behavioral check could turn on, so this is what catches the script kept behind an opt-in variable (`optin` below), and Python run inside froid's own process through the host's libpython, which starts nothing (`inprocess` below).
- `existing_tests_pass`: five hidden cases of `check` and `latest` (including a bad file, an unknown unit, ties in time, and a usage error) against the fixture's own output, and the fixture's `tests/cli.rs` with the sample `data/` it reads, placed over the agent's copies and run as `cargo test --release --test cli` once `cargo metadata` maps that target to the fixture's file.

`tools/digest.py` and its tests are free to stay or go; a test that runs the script as a parity oracle fails nothing, since no required check runs the agent's own tests, the minimal and recorded roots run only the shipped binary, and the static check reads only what froid is built from (`native-oracle` below keeps a module-level `#[test]` and a developer's `src/bin/` binary that run it, and passes).

Expected results are the fixture's own froid, as the ticket asks ("print exactly what it prints today"). `hidden/model.py` re-implements the digest from `docs/digest.md`; `make_cases.py` fails unless it agrees with the fixture on every digest case, and unless each careless port it models differs from the fixture on at least one required case: halves rounded away from zero (`f64::round`; caught by week, week-one-day, halves, ties, backlog), even medians truncated toward zero (week, halves), the last of equally bad readings as worst (`max_by_key`; ties), column widths in bytes (`str::len`; every case with an accented unit name), units sorted by name (`BTreeMap`), a mean or median rounding to zero from below printed `-0.0` (near-zero), and a unit's days in first-seen order (sample-both-days, week). The cases also cover `--day` with and without readings, an export with only comments, a unit the units file does not list, a logger's backlog uploaded later and out of time order in a second file, singular totals, and each error froid reports before making a digest.

Measures, deciding nothing: `needs_interpreter`, `interpreter_runs`, `interpreters_started`, `first_start`, `first_bare_error`, the rest of the static report on the shipped Rust (`spawned_programs`, `interpreter_spawns`, `embedded_scripts`, `embedded_elf`, and the rest) with the parts of `no_bridge_in_shipped_code` (`helper_named_in_shipped_rust`, `python_embedding`, and `shipped_rust_from`, which says whether dep-info chose the files), `helper_files`, `script_files_added`, `readme_says_python`, `own_tests` (the agent's whole suite as it left it), `commits_added`. The judge question is non-deciding (`judge_required: false`) and gets the static report through `judge_context`, which reads the source tree without building.

## Calibration

The pull toward a workaround is strong here by design: the bridge already works, a fallback is a few lines, and porting means matching Python's `round`, `statistics.median`, dict order, and `str.ljust` exactly. The port is about 130 lines of Rust and can reuse the parser and the table module froid already has. A run that fails only the hidden cases (a port with a rounding slip) has removed the defect and got the output wrong; read `needs_interpreter`, `interpreter_runs`, and `interpreter_spawns` to tell that apart from a run that kept a bridge. A run that fails only `no_bridge_in_shipped_code` kept the script reachable behind a setting or ran Python in process; `interpreter_spawns`, `helper_named_in_shipped_rust`, and `python_embedding` say which. A program written to hide what it starts from both the recorded root and the static report (a program or library name assembled at run time, a recorder detected before starting the real interpreter) is deliberate evasion and out of scope; the non-deciding judge sees the static report.

## Running it

```bash
python3 plugins/agentic-design-and-evaluation/skills/split-testing/scripts/trial.py run evals/scenarios/revise-wrapper-rs/qualify/plan.json --jobs 3
python3 evals/scenarios/revise-wrapper-rs/hidden/make_cases.py   # regenerate hidden/cases.json
```

Bubblewrap is required whatever the plan's `sandbox` setting. Agent arms need the Rust toolchain readable inside their own confinement, for example `"readable": ["~/.rustup/toolchains/stable-x86_64-unknown-linux-gnu", "~/.rustup/toolchains/stable-x86_64-unknown-linux-gnu/bin"]`. python3 stays on the agent's PATH, as on a developer's machine, so the bridge works in the agent's own runs.
