# Mermaid

You SHALL produce or revise Mermaid source that faithfully serves the actual assignment and its intended consumer. Choose a suitable diagram family and composition using the relationships and questions that matter. A flowchart is one option; any family the receiving renderer supports remains available. Existing examples and documentation indexes are not a whitelist.

Default delivery can be a Mermaid code block or source file. Preserve an explicitly requested artifact or integration interface. A simple source diagram does not require an HTML application, build pipeline, auxiliary report, or network access. Discover actual renderer support when compatibility materially affects delivery; do not infer support from a different renderer or a moving website's catalog.

You SHOULD retain relevant identity, direction, cardinality, units, qualifications and source relationships. Distinguish observed paths, expected paths, proposed mechanisms and authority where losing that status changes interpretation. An arrow can describe order, dependency, influence or a hypothesis; make consequential meaning recoverable. Avoid implying causation or certainty solely through geometry.

You SHALL preserve important source wording and legitimate distinctions when revising layout or syntax. Treat untrusted labels as data for the selected syntax. A duplicated display label need not denote the same object; stable identifiers help when relationships or annotations depend on identity. Choose detail for the reader without hiding a consequential exception or forcing one view to express everything.

Use [the official syntax reference](https://mermaid.js.org/intro/) or the receiving environment's maintained compatibility information when needed. Documentation examples may target a newer version or optional layout engine. An unsupported feature can warrant an equivalent representation or an explicit limitation while retaining the original source; do not silently install or upgrade a renderer.

Use the [Mermaid diagram reference](references/mermaid-diagrams.md) to explore documented forms, sourced descriptions and syntax links. Select syntax supported by the receiving renderer and consult the linked originals where compatibility or meaning needs closer inspection.

You SHALL verify the properties on which the delivery claim depends. A parser result does not establish readable typography or faithful meaning, and a successful render can omit or obscure content. Inspect actual rendering when that property matters and a permitted environment is available. Preserve errors and limitations when it is not. Do not add a recurring preview loop or require another agent solely because the output is a diagram.

Diagrams can support investigation, explanations, comparisons, annotations and handoffs. Use them when they contribute; a prescribed count or roster would not establish that contribution. [Sources and visual handoffs](../../references/sources-and-handoffs.md) describes the shared custody and interpretation boundary. A recipient may correct or replace the representation and may find something it omitted.
