# Context and Source Evidence

You SHOULD measure context at the host boundary that actually loads it and connect the observation to a named decision or execution trajectory. You SHOULD include passive metadata, tool schemas, injected repository instructions, and condition-specific prompts when consequential. Total package size, file count, and prompt length are weak proxies: smaller context can cause wandering, while relevant guidance can prevent a material omission. A claim of behavioral benefit needs evidence on the affected model, host, and kind of work. A broken path, omitted source, stale identity, or contradiction can instead be repaired and checked at its actual source or delivery boundary without starting a comparative investigation.

You SHALL keep essential execution guidance locally sufficient. External documentation supplies authority, current evidence, or optional depth rather than becoming an undeclared runtime dependency. Organize local references around decisions that can be made independently; add an index, table of contents, or split only when navigation materially improves. You SHALL NOT infer a navigation defect from a line count.

You SHOULD prefer official primary authority and verify that the cited page supports the consequential claim. You SHOULD choose a source horizon deliberately:

- a canonical rolling link for instructions intended to follow current stable policy or behavior;
- an immutable version or commit permalink for reproducibility, historical claims, exact compatibility, or fixed-release behavior;
- a supported release-family link when the contract intentionally follows that line; and
- a moving development source only when movement is intended and clearly identified.

You SHALL record the exact consulted revision in retained evaluation evidence when reproducibility matters, even when the instruction appropriately uses a rolling canonical link. You SHOULD treat redirects, missing anchors, authentication, and unavailable sources as observations requiring interpretation. You SHALL retain a reopening condition when an upstream change could invalidate the conclusion.

Repeated loading can waste context or recover material lost through truncation, compaction, or source change. Trace actual exposure before deciding which occurred. A reference's presence in a bundle is not proof it was read; a “read earlier” note does not restore its meaning. You SHOULD examine whether a continuation or handoff lets the recipient reconstruct consequential understanding from the original assignment and evidence, with the sender's conclusions distinguished from verified state and actual authority. Preserve completed effects so reconstruction does not repeat them.

Shared resources need an actual delivery and ownership contract. You SHOULD inspect what the installed recipient receives, which resources are required, and where their navigation is maintained. An existing file does not validate a copied chapter map; a working full-package link does not establish standalone delivery. A source snapshot can establish provenance without becoming a permanent runtime dependency or a test that forbids legitimate edits to the maintained source.
