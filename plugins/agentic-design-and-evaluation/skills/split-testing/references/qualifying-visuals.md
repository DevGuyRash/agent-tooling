# Qualifying visual behavior

Select observations for the capabilities used or changed and the actual delivery claim. Shared-library changes can require wider coverage than an authored report. Reuse applicable retained evidence for unchanged behavior and obtain new observations for changed inputs, affected dependencies or a consequential unresolved concern. The scenarios below support that selection; a small composition need not exercise capabilities it does not use.

Qualification must distinguish source/model evidence from observed native behavior. Use representative small and large containers, a narrow embedded report in a wide page, light/dark/custom themes, long and repeated labels, missing values and failures. Exercise grouped/type-filtered and regex search-to-evidence and return, menu transit and Escape, modifier-assisted multi-selection and deselection, independent and nested expansion, text selection, Reset/zoom/pan, drafts, unavailable saving, and full-context exports at non-default zoom. Reopen a generated reviewed copy in a fresh browser page and verify original evidence and annotations together, including group members, quotations, excluded feedback and a separate complete backup. Check initial restoration and rapid appearance changes without confusing a modeled delayed-storage test with actual file-origin saving. The library’s native runner can help, but it does not inspect every authored composition or establish assistive-technology quality.

When local file opening or another native capability is administratively unavailable, state that boundary precisely. Rendering the assembled bytes inside a native browser page can establish useful layout and interaction observations; it does not establish file-origin permissions, local storage durability, operating-system handoff, or successful offline opening from an unrelated folder. Do not label those unexecuted checks as passed. Complete the independent review and native observations required by the actual delivery claim before treating those properties as qualified.


Check inner layout, not only document width. Open initially closed components, resize an embedded container inside a wide page, and verify that adjacent controls do not overlap. Open Evidence, pin and unpin it, and verify that the drawing regains its width and the selected mark remains reachable. The reader should not cover figure commands or surrounding explanations. Long status words should stay intact, long source/code lines should scroll in their own reader, and selected records should retain their field structure and citations in expanded views. For diagrams, inspect complete graphical extents—including lines, arrowheads, icons and labels inside their boxes—at natural size, narrow fit and zoom; inspect the exported drawing too. A larger outer viewport alone cannot repair text clipped inside an HTML label. Check source text directly against the supplied source; standard renderer labels can be implicit in a diagram type. Inspect short landscape windows as well as narrow portrait layouts. Confirm that source-reader Escape returns to the original expanded figure, that links out of evidence readers reach their destinations, and that switching reading modes keeps the evidence at the reading line. Inspect the assembled file after rebuilding maintained sources; preview-only CSS changes do not qualify a reusable fix.

## Reader comparison controls

Use the shared figure tools and collection workbench rather than adding a second toolbar, checkbox wall or in-flow interaction guide. Select complementary evidence views according to the actual question; the reading controls do not prescribe a report structure or a fixed number of alternatives. Large selected sets use a width-aware reading window, optional pinned reference, or all-card rows. The reader may link relative vertical scrolling, but that is not paragraph alignment, metric comparability or evidence of agreement. Explain any genuine correspondence in the authored evidence itself.

Reading layout, the pinned reference and current comparison window are session arrangements. Use exact-target notes and bookmarks for consequential review records. Review copies regenerate from retained assembly inputs and selected feedback, not the live reader DOM; they must not turn a temporary arrangement into an analytical ordering. Check the resulting handoff against its actual target identity, quotation, source context and unresolved-status explanation. After testing a large comparison, also test Read, an empty set, a narrow container, enlarged text and returning from an expanded figure. Floating help must not displace the drawing, and clearing a selection must leave keyboard focus reachable.
