# Qualifying visual behavior

Select observations for the capabilities used or changed and the actual delivery claim. Shared-library changes can require wider coverage than an authored report. Reuse applicable retained evidence for unchanged behavior and obtain new observations for changed inputs, affected dependencies or a consequential unresolved concern. A small composition need not exercise capabilities it does not use.

Distinguish source/model evidence from observed native behavior. Rendering a specification to a string (`renderReport` also runs under Node) shows what markup the data produces; only a browser shows layout, interaction, themes and drawn diagrams. Use representative small and large trials, many arms and cases (the tapestry transposes when there are more than eight arms, fewer cases than arms, and no case groups), long and repeated labels, missing values, failures, invalid runs, thin samples and untrusted text that looks like markup. Exercise light, dark and system themes, phone and wide widths, keyboard-only use of the run drawer and ledger (Enter, arrow keys, Escape and the return of focus), ledger filtering and sorting, and forced colors when the claim covers accessibility. A browser run does not establish assistive-technology quality.

When local file opening or another native capability is administratively unavailable, state that boundary precisely. Rendering the assembled bytes inside a native browser page can establish useful layout and interaction observations; it does not establish file-origin behavior, storage of the theme choice, or successful offline opening from an unrelated folder. Report those checks as not run.

Check inner layout, not only document width. Wide tapestries and tables should scroll inside their own region, labels and status words should stay intact, the section index should stay reachable, and the run drawer should fit a phone-width window. For diagrams, inspect complete graphical extents, including lines, arrowheads and labels inside their boxes, at natural size and in a narrow container, and check text directly against the supplied source. Inspect the assembled file after rebuilding maintained sources; preview-only CSS changes do not qualify a reusable fix.
