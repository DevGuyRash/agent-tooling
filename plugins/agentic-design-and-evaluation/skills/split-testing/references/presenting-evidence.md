# Presenting evidence

A report is optional: use one when a reader needs to inspect, decide from, or return to the evidence, and let a short answer stand when it serves. For a trial, the quickest faithful path is `trial.py report RUN_DIR --out trial.json`, then `assets/visuals/report.py --trial trial.json --narrative narrative.json --output report.html`. The narrative carries the decision you reached by applying the plan's rule, readable labels for arms and cases, the arms that received identical material, and any extra sections; the composition already shows every run, invalid runs, intervals, checks, pairwise judgments, cost, and the plan. The [visual library catalog](../assets/visuals/catalog.md) describes the narrative, every block for a specification of your own, and what each view keeps faithful; [packaging reports](../assets/visuals/PACKAGING.md) covers custom compositions, the offline contract, and checking a file before delivery; [Mermaid diagrams](mermaid-diagrams.md) and [qualifying visuals](qualifying-visuals.md) cover diagrams and checking rendered views. The library offers views; it never decides what the report says or requires every one.

Open with the question and the decision, with enough purpose and context for the reader to know what was compared and why. Put the conditions that could change the decision beside it, then order the rest around the reader's decisions. Explain the practical question and finding in ordinary language while keeping exact measures, units, source identities, and distinctions.

A view is faithful when it keeps failures, missingness, ties, vetoes, and invalid runs visible; invents no scores, weights, rankings, or uncertainty; keeps development findings apart from fresh confirmation; and lets the reader reach the native record behind each consequential claim. Aggregation, collapsed content, ordering, color, and interaction are part of the evidence: an attractive overview that hides a consequential exception is inadequate. Color reinforces a distinction that words or marks also carry.

Choose views from the evidence: requirement coverage, paired observations, distributions and tails, changes across rounds, trade-offs, qualitative excerpts, objections, provenance, and cost are common, and none is mandatory.

A standalone HTML report is one self-contained file with its styles, scripts, data, fonts, and images embedded, so it opens offline without a server or build step; the working files and native evidence stay in the run or context directory. Before delivering it, open it from an unrelated location without network access and check values, missingness, layout, keyboard access, and safe display of untrusted evidence text. A report that renders correctly says nothing about whether its analysis is valid.
