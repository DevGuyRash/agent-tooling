# Composable Visual Presentations

This library presents caller-supplied observations, approved interpretations and their grounds. It does not assess candidates, calculate scores, estimate uncertainty, determine confidence, infer frontiers or choose a winner. Legitimate supplied measurements, confidence judgments and conditional recommendations remain representable. Choose the views that help the actual reader; neither this catalog nor the demonstration is a required report structure or a complete account of useful representations.

The public TypeScript API is [`src/index.ts`](src/index.ts), which exports the data and composition interfaces. The compiled browser API uses the same function names under `window.AgenticVisuals`. Every renderer returns an HTML fragment. The optional `evidenceWorkspace` composition adds navigation around selected fragments, and `enhanceVisuals` activates progressive interactions after insertion. Compose selected fragments with ordinary narrative and task-specific figures, then embed the required stylesheet and compiled scripts through the offline packaging tools. [`examples/demo.ts`](examples/demo.ts) exports `renderDemo()` and supplies synthetic inputs covering the catalog. Its fictional field-notebook study covers every presentation through task-focused views; its values are demonstration material, not evaluation evidence. The stable stylesheet is [`styles/agentic-visuals.css`](styles/agentic-visuals.css); applying `av-report` to a containing element also styles the page background and top-level title.

## Shared input and presentation behavior

Data renderer inputs include `title` and can include a document-unique `id`, `description`, `note`, `evidence` and `limitations`. An evidence reference is `{ label, href?, note? }`. Each renderer's item types expose notes and evidence where the relevant finding or relationship occurs. A cell is `{ value: string | number | null, status?, note?, evidence? }`. Status is one of `supported`, `conditional`, `uncertain`, `missing`, `failed` or `not-applicable`; the caller assigns it. A named row, column or node is `{ id, label, note?, evidence? }`. Entity IDs must be unique within their declared set. An optional renderer `id` provides a stable link and notebook target in the containing document; it starts with a letter and uses letters, numbers, underscores, periods, colons or hyphens. This document ID is separate from supplied analytical entity IDs. Duplicate matrix cells and undeclared relationships are rejected instead of silently overwriting evidence.

Display labels may repeat. Record and scenario collections without authored entity IDs use visible occurrence numbers when labels repeat, consistently across selectors, comparison choices and reading panes. These numbers describe supplied order, not rank or cross-revision identity; the original text and internal command keys are retained. Matrix, heatmap, constraint, journey and unknowns views retain the supplied stable IDs alongside colliding names, including the headings for their notes and evidence. Collision checks use each complete declared set and include label whitespace that HTML collapses; distinct labels remain concise. Focused journeys retain alternative IDs, and graph, scatter and uncertainty inspectors retain their existing explicit identities. IDs identify the supplied entities and do not imply order, rank or a new analytical category. Keep the same IDs when rearranging an existing comparison; changing which ID a finding references changes its attribution.

Quantitative components require finite JavaScript numbers. `null` explicitly records missing measurements; omitted optional interval fields are also missing. Numeric strings, `NaN` and infinities are rejected with `TypeError`. Large finite, negative, zero, constant and very small values are supported without fixed pixel-per-unit arithmetic. The domain is derived from the supplied values, without requiring zero. A constant domain places its value in the middle. Direct finite differences preserve relative spacing even for close representable numbers; normalization is reserved for domains whose direct span would overflow. Axis ticks are approximate labels, with duplicate rounded ticks removed. When compact labels would otherwise be indistinguishable, the axis states an additive offset explicitly (for example, “Add 0.1 to tick labels”). The data table preserves the full JavaScript number representation, including negative zero. This is not arbitrary-precision arithmetic: values that need precision beyond a JavaScript number belong in text cells or a separately reviewed exact-decimal renderer. Separate plots can have different domains; do not compare their visual lengths as though the axes were shared.

Labels wrap using shared text metrics and grapheme boundaries, with no substring ellipses. Horizontal tick labels use separate rows when measured bounds would overlap, and the scale area grows to retain the complete labels and units. Static output uses conservative measurements; optional hydration refines geometry using the actual browser font while retaining live plot roots and selected marks. Content bounds include node and relationship boxes, labels and arrowheads. Very dense graphs may still contain edge crossings; crossings do not declare relationships. Each numeric plot and graph includes a semantic data table with exact values, missing entries, notes and evidence. Native disclosure controls expose those tables with the keyboard and work without application JavaScript. Enhanced plots fit the available width automatically and grow to show all retained rows at reset. Zoom creates bounded pan space inside the visualization; a hand cursor, mouse/pen drag, touch scrolling and keyboard scrolling expose it without visible chart scrollbars. Row identities keep their fitted width and type size while their vertical positions follow the observations; the numeric scale follows horizontal pan. Other overflow containers retain themed scrollbars. The unenhanced version scrolls as a natural composition. The library imposes no alternative or observation-count limit. Very large datasets can still exceed browser memory or become hard to inspect; select a more suitable task-specific view or split a view with explicit scope, preserving the complete retained data. SVG hover titles supplement the tables and are never the only route to an observation.

Text is escaped, including titles, labels, notes and artifact contents. Evidence URLs are user-activated HTTP/HTTPS links or same-document fragments; unsupported or malformed URLs remain visible as omitted links. Links do not load their targets automatically, and external citations need connectivity when the reader chooses to follow them. The containing report must supply any fragment target it references. Essential supporting evidence must itself be embedded or reproduced when offline inspection depends on it. The library uses system fonts, SVG and native HTML controls. Its HTML is readable without hydration; optional interaction code adds focus inspection, navigation and exploration. Neither path needs a runtime framework, remote assets or fetching.

## Workspace and interaction composition

The report bar uses shorter visible reading-mode labels in small containers without changing accessible names or command hooks. Switching between section and full-report modes retains the reading position; returning from the full report uses the section at the reading line. Very narrow containers stack their utility row instead of overlapping buttons.

An expanded figure keeps Close or Back beside its title, its live commands on the next row, and optional **Context and sources** beneath. Selecting an inspectable observation opens its formatted evidence there. **View source** opens a separately sized native source dialog; Escape returns to the still-expanded figure without resetting its view. The source stays literal and read-only, including whitespace; optional soft line wrapping changes only its display; the dialog is omitted from regenerated review copies. A native details reader is the fallback without dialog support.

The shared note editor keeps its actions separate from its scrolling text area. Control+Enter or Command+Enter saves; Escape keeps an edited draft and returns to the originating control. These shortcuts do not act during IME composition. The aggregate notebook closes when editing a note, preventing a competing panel from covering it. Unresolved bookmarks remain visible and can be explicitly removed from the notebook without matching them to current evidence. Draft saving and browser durability are different states; retain the visible storage qualification.



### Drawing tools and large collections

A figure has one compact command bar. **Pan**, **Select**, and **Text** are modes in its labelled Drawing tools panel; keyboard and touch help is inside that floating panel, never an expanding block above the drawing. The same controls move into overflow as space decreases. A contextual **N selected** or **Passage** button appears only for a current selection, opening inspection, note, bookmark, clear and additive-selection actions. Pan does not select items; Text uses the browser's passage selection. Control/Command toggles an item, Shift selects a range in supplied order, and their combination adds a range. Add to selection supports repeated touch taps. Empty selection leaves no reserved action row. Escape closes the active panel and returns to a reachable control, including overflow.

Record and scenario collections use **Read / Compare** with a searchable **Records** picker. The chosen set is independent of the reading window: selecting many records never divides the available width by the full count. **Reading panes** shows one to four comfortably sized records, depending on container and text size, with Previous/Next windows. A pinned reference remains beside each window; narrow containers offer a full-width Reference switch. **All cards** displays the entire selected set in readable rows rather than narrow columns. Source order, exact labels, missingness and the original live evidence nodes remain intact; pinning is a reader choice, not a recommendation or analytical ranking. Legacy `data-av-select` and `data-av-compare` commands remain supported.

**Scroll together** is optional and off by default. It links relative vertical progress in the currently visible reading panes; either pane can lead. Equal scroll progress does not assert that paragraphs or measurements correspond. Paging retains each record's reading position. Opening a record outside the chosen set returns to Read without silently discarding that set. These are in-session reading arrangements, not durable annotations: annotate or bookmark the exact evidence to include it in the notebook, reviewed report or handoff. Native fallback and printing retain all original records. Review identity uses the canonical author order while reading arrangements move the live nodes; real edits, missing targets and ambiguous identities still produce unresolved annotations.

`evidenceWorkspace(WorkspaceInput)` wraps caller-selected views with an optional navigation shell. Each view has a unique `id`, `label`, optional `description` and `icon`, and a trusted `body` HTML fragment. The workspace has a unique document `id`, `title`, optional `description` and `label`, optional authored `brief`, `views`, and optional trusted `footer`. An opening brief appears before reading routes and exploration controls; a clear title and description serve smaller compositions. In Section view, the panel repeats a compact link to the question/title so shared and resumed views retain their report context. Full report suppresses those repeated context links. IDs start with a letter and contain letters, numbers, underscores, periods, colons or hyphens. The optional icon choices are `overview`, `compare`, `plot`, `evidence`, `scenarios`, `unknowns` and `history`; they are decoration, not a classification requirement. Choose any number of views or use individual components without a workspace. One delivered report has one workspace shell; nested workspace shells are rejected before enhancement changes anything. Charts, sections, lanes and themed surfaces remain nestable. Independent sibling reports can use `landmark: "region"`; the default top-level shell uses `main`. Each sibling owns its controls and reader state.

Titles, descriptions and navigation labels are escaped. `body` and `footer` are executable authoring composition, like the packager’s body fragment: use renderer output or reviewed markup, never untrusted evidence text. Same-document references need their actual target in the delivered report. Workspace panels are all present and readable as an ordinary document before hydration; their anchors work without application JavaScript.

After inserting a fragment, call `enhanceVisuals(rootElement)`. The function returns an idempotent callable cleanup that removes its listeners and generated controls and restores managed visibility. Its additive `whenReady(): Promise<void>` waits for initial owned display/notebook restoration; `whenIdle(): Promise<void>` also drains queued persistence, search, diagram and export/import work. Neither method turns unavailable saving into a durable save. Callable `cleanup()` callers remain compatible. Repeating enhancement on the same root returns the existing cleanup function. Use one root for a report, or separate non-overlapping roots for independent reports; overlapping ancestors and descendants are rejected before a second controller is attached.

A report-wide sticky bar keeps search, Display and the aggregate notebook reachable while reading. The same settings and notebook panels use the native top layer when available, retaining their original DOM ownership and theme. Workspace layout responds to its own container, not only to the browser width. A single-view report omits redundant section navigation and reading-mode controls; it remains a normal composition with the same figure and review tools. Larger enhanced workspaces provide Section view and Full report. Full report retains the current section for returning. Search groups sections, figures, identified items, report text, notes and bookmarks. Reader records are searched only inside their owning report; the search does not send evidence or queries anywhere. All types initially show at most three matches each; type filters and Show more expose the rest without burying other categories. Literal text is the default. Regex accepts a pattern or `/pattern/imsu` and runs in an isolated, terminable worker; an invalid expression, unavailable worker or one-second matching deadline leaves an explicit result and the report responsive. Selecting a result reveals its original section/disclosures or notebook entry, without inventing a score or changing evidence. Original control labels and repeated navigation context are not indexed. Arrow keys move through results; Escape clears search and returns to its field.

Expand opens the original frame in a native dialog and moves its section actions into the dialog bar. A closed frame opens for inspection. Close restores the frame, prior disclosure state, viewport and focus. Every visualization keeps a persistent command strip immediately above its drawing; descriptions and evidence selectors stay outside that strip. Reset, + and − fit and navigate the canvas. Pan, Select items and Select text distinguish navigation from inspection and passage selection. Pan taps do not select items. In Select items, Ctrl/Command toggles membership; Shift replaces the range in source order; Ctrl/Command+Shift adds that range. Add to selection provides the additive operation without a modifier on touch. Arrow keys move, Shift+arrows extend, Control/Command+A selects identified items, and Escape clears; these keys do not override native input editing. Text mode disables drag-panning and interactive hit overlays. Its Note and Bookmark commands require a current exact passage, never an old item selection. Selection controls show the active count and offer explicit Inspect, Note, Bookmark and Clear actions. The same live command nodes move into a three-dot overflow as available width decreases; expanding restores the appropriate allocation for the larger view. Controls remain visible without hover.

The overflow closes on outside interaction, Escape, focus leaving the menu, or choosing an action. Moving the pointer between the trigger and commands does not dismiss it. It opens above the trigger when space below is insufficient. Browsers with native popovers lift the menu above scroll clipping; the fallback sizes and places it within the containing scroll region. Its keyboard controls include arrow navigation and Home/End. Copy-source copies the original source directly; View source and source download remain separate menu actions. Section commands use the same overflow primitive. Temporary outcomes use a shared themed bottom-left notification stack: at most three active messages, consistent alignment with content-sized readable messages, automatic expiry, hover/focus pause and explicit dismissal. Success has a green check; failed copy/export actions retain a practical fallback. Notifications from an expanded view remain in its modal layer.

Pointer selection updates the inspector without jumping the page to it; keyboard activation retains a focus path into the selected evidence. Artifact and scenario readers show the selected native record in a consistent-height pane. Explicit comparison uses equal-height, width-aware reading windows or all-card rows, with independent scrolling unless the reader enables Scroll together. A direct reference to a chosen record brings it into the reading window; another record opens in Read while retaining the chosen comparison set. When space permits, the inspector aligns with the drawing, with its height derived from the plot and available viewport rather than a small fixed box. In narrow containers, Inspect or Read evidence opens the same live records in a separate closable reader; closing returns to the initiating control. Long identities wrap and wide relationship tables scroll inside that reader. Item selection uses theme-colored emphasis rather than a white bounding rectangle, without replacing authored filters or semantic fill/stroke. Original evidence stays in the document, available through its selector and exact-data views. These fixed reading panes are distinct from the report’s freely collapsible top-level sections. Reset and relative zoom preserve source-owned axes, labels and marks; theme, navigation and control relocation do not replace observations or reader records.

An optional `startView` names the initial workspace view. Optional `journeys: { id, label, description?, viewIds }[]` supply author-defined paths through existing views. Each path has distinct declared steps; it offers previous/next navigation and a way to leave it. Ordinary navigation stays available. A link outside the active path leaves that path; Full report temporarily hides its step controls and retains the path for returning. With no journeys, the workspace supplies no guided sequence. The standalone `readingGuide({ title?, description?, routes: { id, label, description?, href }[] })` renders native same-document choices for arbitrary composition; those destinations must exist in the delivered document. Only a workspace with matching journey declarations adds step behavior.

`comparisonJourney(MatrixInput)` explores one alternative’s supplied requirement findings at a time with selection and previous/next navigation. All alternatives remain present and the complete matrix remains available. Supplied order is navigation order, not rank. `uncertaintyObservatory(UnknownsInput)` opens each unanswered question with its relevance, affected alternatives and consequences, retaining the complete unknowns map. Its categories have no numerical magnitude or implied confidence.

## Display preferences and reusable sections

Each data renderer returns a native collapsible section, initially open. Set `open: false` for a closed initial section or `collapsible: false` for an ordinary frame. Titles, observations and supporting evidence remain in the HTML. Table captions retain accessible names without repeating the visible section heading.

`appearanceSettings({ id })` provides appearance, palette, canvas, spacing and disclosure controls. Its radio groups need a document-unique ID. Place it inside `reportSurface({ id, body, theme?, palette?, customColors?, canvas?, texture?, intensity?, spacing?, sections?, storageKey? })` or an `evidenceWorkspace`; the containing surface supplies the initial preferences. Theme values are `system`, `light` and `dark`; spacing is `comfortable` or `compact`; sections are `multiple` or `solo`. Preset choices are `indigo`, `ocean`, `graphite`, `aurora`, `citrus` and `rose`, plus `custom`; canvas is `ambient`, `plain` or `textured`; `texture` is `grain` or `grid`, and `intensity` is `low` or `moderate`. Plain retains a flat themed base, Ambient uses restrained gradients, and Textured adds the selected background pattern. Defaults retain low intensity and grain when texture is chosen. Defaults are system appearance, indigo, ambient canvas, comfortable spacing and multiple open sections. `evidenceWorkspace` includes the panel unless `settings: false` is supplied. Hydrate the containing element with `enhanceVisuals` after inserting its complete composition.

`reportSurface` gives arbitrary fragments their own preferences without imposing a workspace or navigation. `reportSection({ title, body, description?, open?, ...annotations })` makes a native section around trusted author composition. `sectionGroup({ body, mode? })` defines peers; omit `mode` to follow the surface preference or supply `multiple` or `solo` for an explicit group behavior. Solo mode keeps at most one peer section open, including when a link or an inspector reveals one. The section being used stays open when the reader enables solo mode. Fixed inspector reading panes follow the current item selection; other item disclosures use their own peer group. Nested groups, ordinary data disclosures, settings and explicit artifact comparisons keep their own behavior. In section view, top-level sections share their current view’s group. In Full report, those sections share one reading group across views; explicit section groups and nested comparisons remain independent. Switching navigation modes retains and reapplies the selected opening policy. Expanded inspection temporarily exposes a closed frame without changing its report peers; nested groups retain their own opening policy. Existing closed state remains closed when returning to multiple-section mode until the reader opens it.

For example, a small composition can contain a Display panel, custom context and a normal data renderer:

```ts
const fragment = reportSurface({
  id: "capture-review", theme: "system", sections: "multiple",
  body: appearanceSettings({ id: "capture-display" }) + sectionGroup({
    body: reportSection({ title: "Decision grounds", body: "<p>Approved context supplied by the author.</p>" })
      + annotatedTable({ title: "Observed results", columns: ["Case", "Result"], rows: observations }),
  }),
});
```

Section and surface bodies are trusted author HTML, like a workspace view body; untrusted evidence belongs in escaped renderer inputs. Native sections remain usable without application JavaScript, while enhancement-dependent settings stay hidden. Choose one enhancement root for a composition, or separate non-overlapping roots for separate compositions. Cleanup restores managed markup and initial disclosure state. Expanded inspection carries the source surface's appearance, palette, canvas and spacing, and restores keyboard focus to a visible summary if the reader folds the inspected section.

Persistence is opt-in through a nonempty `storageKey` and a stable surface/workspace ID. Preferences use the shared transactional browser store with a distinct record kind and owner; they merge changed fields into the latest record. Foreign kinds/owners or malformed legacy values stay protected. Previously saved localStorage values can be imported without deleting or rewriting their original bytes. When IndexedDB is unavailable, current-session choices still work and the Display panel exposes the saving limitation. Cleanup cancels late loads and restores initial markup.

`src/theme.ts` owns presets, choices, defaults, role derivation and the supported `--av-palette-*` overrides. The generated stylesheet combines that definition with `styles/components.css`; `build.mjs --check` checks both the runtime and generated style for the default library output. Main, Secondary 1 and Secondary 2 affect canvas, raised surfaces, headings, tools, inspectors, actions and selection through distinct roles. Custom colors use the same role generator. `customColors` requires `main`, `secondary` and `tertiary` six-digit hex values and optionally accepts `backgroundLight` and `backgroundDark`. Display exposes both canvas colors when Custom is selected. Raised surfaces, readable text tones, ambient washes and scrollbar colors derive from the selected canvas; existing three-color inputs remain valid. A standalone workspace also themes the document scrollbar, while embedded sibling reports keep their own scroll-surface ownership. Semantic hues retain their meanings while adjusting contrast on custom canvases, and every categorical color slot remains visible against its drawing surface. Native image colors remain separate; categorical markers supplement colors with shapes/patterns and visible codes when needed. Sequential heat colors have ordered luminance and exact visible numbers. Palette changes alter presentation without changing source data.

The display system requires browser `color-scheme`, `light-dark()` and sRGB `color-mix()` support. Authors may override the declared `--av-palette-*` primitives and remain responsible for contrast of those overrides. A bare interaction root inherits its owning surface instead of acquiring default appearance settings. Expanded inspection retains the effective owner and supported nearer overrides. An explicitly authored nested `reportSurface` remains an independent override scope even when only the outer report exposes settings.

[`examples/snippets.ts`](examples/snippets.ts) composes independent dark/compact and light/comfortable surfaces without a workspace. Its exported `renderSnippets()` can be compiled and assembled by the same documented tools as the full demonstration. It illustrates composition choices, not a required report layout.

## Narrative, parallel reading, and personal records

`reportBrief({ question, id?, paragraphs?, facts?, finding?, findingLabel?, body?, note?, evidence? })` establishes the actual comparison question or task. Paragraphs accept the same escaped inline text as story panels; facts accept authored labels, text, status and supporting evidence; a supplied finding uses “What the evidence supports” unless an author supplies another label. Omitted optional content adds no placeholder or invented conclusion. The trusted `body` permits additional composition of any needed depth. Use it as a workspace's `brief` or place the fragment at the start of a custom report. Authors provide the substantive context and choose the subsequent order; the component supplies a consistent opening surface without imposing the rest of the report.

`storyPanel(StoryInput)` accepts optional `lead`, `paragraphs` and `takeaways` within the shared frame. A takeaway supplies `label`, `text`, optional `status`, notes and evidence. Text can be a string or segments `{ text, tone?, strong? }`; `inlineText` renders the same segments for custom composition. Tones are `plain`, `accent`, `positive`, `caution`, `negative` and `muted`. Authors supply their meaning; the renderer escapes text and preserves whitespace. Keep important conditions in the visible wording so color supplements an understandable claim.

`comparisonLanes({ title?, description?, lanes, sectionMode? })` composes named `{ id, label, body }` lanes. Each owns an independent disclosure group and content flow. They sit alongside one another when the containing width permits and stack in source order when it does not. Position alone establishes no equivalence or shared scale. Ordinary fragments default to a vertical reading flow; use lanes when readers benefit from an intentional parallel comparison.

`researchNotebook({ id, scopeId, revision, storageKey?, activityLimit? })` can sit inside its identified `reportSurface` or workspace. A workspace can instead accept `notebook: { revision, storageKey?, activityLimit? }` and supplies the IDs. The notebook retains reader notes, bookmarks, current view/path and recent reading actions. Keep one notebook for the report; it targets that report, its views and identified renderer frames. Independent sibling reports keep separate ownership. Repeated destination titles include their containing view or a stable-ID fallback consistently in selectors, notes, bookmarks and activity. Stable IDs and a new revision for changed meaning prevent a note silently moving to different evidence. These personal records do not replace retained experimental outcomes or adjudication records.

With no storage key, records stay in the open document and can be exported. With a key, browser-native IndexedDB transactions apply edits against the latest stored state. Navigation and bookmarks cannot replace unrelated notes from another open copy. Independent note edits merge; competing edits or deletions on the same note remain available for explicit resolution. Record kind, report ID and revision are enforced at the storage boundary, including separately enhanced roots. File-origin persistence can be unavailable; the visible status then exposes session-only operation and export.

Prepare notebook export waits for pending edits and reads the latest compatible records; Download notebook copy then transfers the prepared file. Preparation includes current drafts and competing versions. Subsequent changes invalidate that prepared copy. Version-1 and version-2 exports remain importable with their original bytes retained. Version-3 transfers add contextual annotations, draft bases, competing edits and adopted-review identities. Import requires confirmation. Legacy localStorage bytes are preserved during migration, and protected foreign/corrupt records can be recovered without ordinary actions overwriting them. The containing report's identity must remain stable when its meaning is unchanged; a changed analytical identity needs a new revision.

`activityLimit` defaults to 128 and may be zero. Lowering it trims retained activity while preserving notes, bookmarks and place, and updates the discarded-action count. Reading actions never include note bodies/search queries and do not imply understanding or verification. Personal records remain separate from experimental evidence. Async saved-place restoration yields to explicit same-report fragments and intervening reader actions; cleanup prevents late restoration. Reading actions made while records are opening merge into the loaded notebook. An open copy that has already observed an older notebook remains unable to overwrite a replacement.

The exploration canvas uses the available width until a useful reading width is reached. An inspector wraps below it until both fit, then docks beside it without reducing the canvas width. The same sizing applies inside nested compositions and expanded inspection. Automatic fit, Reset, relative zoom and bounded panning retain the supplied data; row plots keep synchronized labels and scales alongside the marks.

## Categorical identity and chart context

`createChartContext({ categories?, width?, measureText? })` creates a shared immutable presentation context. Pass it as `context` on renderer inputs when several charts share category identities or an authored layout width. A category declaration is `{ id, label?, style? }`; styles can choose a series-color slot, marker shape and numeric line dash pattern. The complete declared set determines stable shape/code assignment across views and harmless input reordering. Unknown categories are added locally; provide the complete common set when cross-view appearance must be identical.

Distribution groups and trajectory series accept optional `id`; graph relationships accept optional `id`; scatter groups accept `groupId` separately from their display name. Missing IDs receive explicit occurrence labels within that presentation, not an invented cross-report identity. Tables expose group/series/relationship IDs alongside labels, including repeated labels and empty groups. Numeric geometry and source order are unaffected by style allocation. Monochrome themes retain shape/pattern distinctions, with visible category codes when shapes repeat. Exact legends and inspectors remain the authoritative identity lookup.

The optional `measureText(text, fontSize?)` supplies actual text advances for author-side layout. `browserTextMeasure(document, font)` produces a native Canvas measurement adapter when available. Normal consumers can omit both: static wrapping is conservative, and enhancement requests native-metric refinement without replacing the report's evidence, notes or active marks.

## Differences and requirements

| Renderer | Inputs beyond shared metadata | What it reveals | Limits |
| --- | --- | --- | --- |
| `comparisonMatrix(MatrixInput)` | `alternatives`, `dimensions`, and `findings`, each finding adding `alternative` and `dimension` IDs to a cell | Many alternatives against named dimensions, annotations and asymmetric evidence | Unfilled cells read “Not supplied.” Matrix layout does not imply equal importance, completeness or an aggregate score. |
| `constraintSatisfaction(MatrixInput)` | Same matrix contract, with actual requirement findings supplied as cells | Constraint satisfaction, uncertainty and conditionality together | This is the matrix presentation, not a feasibility solver. No status is inferred from prose. |
| `constraintMap(MatrixInput)` | Same contract | Independently expandable requirement views showing all alternatives and their supplied findings | Collapsing a requirement changes visibility only; it neither waives the requirement nor recalculates viability. |
| `conditionalRecommendations(ConditionalInput)` | `items: { condition, implication, status?, note?, evidence? }[]` | Recommendations and consequences with the conditions that govern them | Approved preferences can be stated in `implication`; the renderer invents none and does not resolve conflicting conditions. |
| `pairedComparison(PairedInput)` | `axis`, optional `unit`, `leftLabel`, `rightLabel`, `pairs: { label, left, right, note?, evidence? }[]`; each side is a number or `null` | Matched numeric observations on one axis, with a circle and square for the two sides | Missing sides get no mark or connecting line. No difference statistic is calculated. Use excerpts or an annotated table for qualitative contrasts. |
| `annotatedTable(TableInput)` | `columns: string[]`, `rows: Cell[][]` | Mixed quantitative and qualitative findings whose qualifications matter | Row lengths must match the column count. The caller supplies units, ordering, interpretation and any approved calculations. |

Shared category shapes, dash patterns and necessary visible codes supplement color, with full series identity retained in the table. | `decisionHistory(DecisionHistoryInput)` | `decisions: { label, when, decision, availableThen, changesSince?, supersedes?, note?, evidence? }[]` | An ordered decision record that separates contemporaneous grounds from later developments | `when` may be a date or a round label; the caller supplies ordering and revision references. The renderer neither rewrites historical judgments nor infers causality. |

## Tradeoffs and conditions

| Renderer | Inputs beyond shared metadata | What it reveals | Limits |
| --- | --- | --- | --- |
| `scatterPlot(ScatterInput)` | Axis labels/units; `points: { id, label, x, y, group?, note?, evidence? }[]`; optional `frontiers: { label, pointIds, note?, evidence? }[]` | Supplied numeric tradeoffs, observed clusters and approved frontier connections | Frontiers join the specified complete points in the supplied order. Point IDs remain visible in both observation and ordered-connection tables, so repeated labels do not erase identity. No dominance, preference direction, optimum or interpolation is inferred. Partial coordinates remain visible in labelled missing-coordinate bands and in the exact data. Labels stay fully opaque for negative and zero values. Missing and absent cells remain explicit. Use comparable units within one color domain; use a coverage matrix for categorical states. |
| `scenarioExplorer(ScenarioInput)` | `scenarios: { label, condition, outcomes: { alternative, outcome, status?, note?, evidence? }[], tradeoff?: ScatterInput, note?, evidence? }[]` | Grounded alternative consequences under discrete supplied scenarios | Native keyboard disclosures can remain open together. ## Figures, diagrams and contextual review

`visualFigure({ id?, title, caption?, body, adapter?, source? })` composes an independently inspectable figure. `body` is trusted author markup; use escaped renderer fields for evidence text. Optional source is `{ language, text, filename? }`. Native library charts and artifact images already declare their figures. Each enhanced figure has Reset, + and −, interaction-mode tools, expansion and export actions. A persistent strip immediately above the drawing exposes the actions that fit; the same controls move into overflow in narrower containers and remain accessible on touch. Expanded figures fit both dimensions. Closing a nested figure returns to the previous expanded section, then restores the original inline viewport and focus.

`mermaidDiagram({ id?, title, source, caption?, config? })` retains exact Mermaid source and declares its embedded renderer requirement. The full bundled Mermaid 12.0.0 parser determines diagram families and supported layouts. Author configuration and source directives can supply meaningful styling; the shared adapter supplies report-theme defaults and keeps strict rendering security and report configuration isolated. Renderer-owned duplicate DOM IDs are scoped without dropping nodes: repeated selectors retain their matching elements, and equivalent duplicated paint definitions remain equivalent. Differing definitions behind an ambiguous fragment reference are not guessed. Analytical item annotations still require unambiguous identity. Failure leaves source and a diagnostic available. See [packaging](PACKAGING.md) for runtime-only composition and offline resources.

`registerVisualAdapter(name, adapter)` returns an unregister function. An adapter supplies `bounds(element): { width, height }` and may supply full-scope `svg(element)`, `png(element)`, `source(element)`, `items(element)` and `identify(target, element)`. SVG/PNG callbacks can return a promise. Items are `{ id, label, text?, values? }`; `identify` returns an unambiguous item ID. Supply stable item identity only where the native representation supports it. Custom HTML bodies use the same fitted viewport; custom renderers supply their image export. SVG output must contain its styles and resources, and PNG output must be an `image/png` Blob. Common export handling adds the title, caption, legends and qualifications, irrespective of current pan or zoom. Clipboard or conversion refusal leaves source/download actions available. Vector exports allow local paint references and embedded raster resources; active content and unresolved dependencies require a self-contained adapter snapshot.

With `researchNotebook` present, sections and figures expose Note and Bookmark actions alongside their controls. Notes can address the complete target, selected text, an identified item or an explicitly selected group of items. Select text mode separates passage selection from panning and item activation; Select items exposes identifiable native context. Contextual Note and Bookmark actions share the figure’s responsive command strip. The aggregate notebook’s Add a note action uses the same content-fingerprinted editor as contextual Note. Escape or switching targets keeps an edited draft; a rejected in-session change leaves the editor open instead of hiding the unsaved text. The aggregate notebook has Notes, Bookmarks, Activity and Share tabs, a fixed reachable Close action, per-tab reading positions and filters for text, drafts and entries needing attention. Note cards expose original evidence, direct navigation and editing; bookmarks expose navigation, Add a note and removal. Activity uses a time-ordered readable list with exact timestamps available, rather than raw ISO text attached to large buttons. Committed annotation/bookmark changes are recorded; draft keystrokes do not flood history. Keyed updates retain record DOM, focus and open evidence while unrelated reader state changes. Multiple notes, drafts and competing edits remain distinct. Older target-only notes remain available in a separate earlier-notes disclosure; their lack of an original fingerprint is explicit, not silently upgraded to verified attachment. Inclusion controls select feedback for a portable copy without deleting the full notebook records.

`ReviewAnchor` records the report/revision, target identity, contextual path, content fingerprint, original wording and source links. Text anchors retain the quote and surrounding text; item anchors retain available native identity and values. An `items` anchor retains each selected identity and its original wording/values as one group. Resolving a group is all-or-nothing: a changed, missing or duplicate member cannot silently leave a partially attached note. Compatible older single-item/text/section/figure records remain readable; an older library without the group extension is not a supported group-record consumer. Numeric negative zero is retained in new JSON reader transfers and handoffs, not normalized to positive zero. Changed, absent or ambiguous material remains explicitly unresolved. Supply persistent document and item IDs to distinguish identical repeated targets. Generated identities are conservative when author data cannot distinguish occurrences.

Download annotated report rebuilds the original assembly recipe and embeds the selected feedback as inert data; it preserves the original report identity and evidence. The receiving report loads that review alongside compatible local records, adopts it once transactionally, and preserves later edits and deletions on reopening. Download or Copy review handoff supplies readable feedback with its question, original target grounds, source references, unresolved attachments, drafts and competing versions. Retain the complete report with the handoff so the receiving executor can consult the original assignment and evidence. Share inclusion applies to feedback, not original report evidence. Annotated HTML and Markdown omit excluded feedback and recovery-only original/import payloads so excluded text cannot leak through a hidden backup. Export notebook JSON is the separate complete recovery transfer: it retains competing versions, drafts and protected older/imported bytes irrespective of sharing choices. Keep that backup private when it contains material omitted from a review. Browser saving failure leaves session records exportable. A stalled transaction becomes an explicit unconfirmed-save state rather than an indefinite saving indication. The handoff puts evidence and feedback inside literal-text fences, preserving Unicode and markup-like wording without letting them create active Markdown/HTML. The original HTML recipe, not the live reader DOM, remains the basis of an annotated report.

## Native artifacts and open extension

`nativeArtifactViewer(ArtifactInput)` accepts `artifacts: { label, mediaType, text?, imageData?, alt?, note?, evidence? }[]`. It shows logs, code, JSON, HTML source and excerpts as escaped, keyboard-scrollable text. It also displays embedded base64 PNG, JPEG, GIF or WebP images with required alternative text. Screenshots, plots generated by an optional local plotting tool and rasterized document pages can therefore accompany the library views. Optional artifact selection opens their retained details; comparison places selected artifacts together while keeping all others available. It never executes HTML artifacts, loads remote images or accepts active SVG data URLs. A declared media type is descriptive metadata, not a parser or format validator; the caller must verify that an image actually decodes and that a document excerpt retains the necessary context. Full documents or other native media can use the packager's reviewed local asset path when the task needs a different viewer.

`renderExtension(ExtensionInput)` is a convenient declarative composition helper: it accepts `purpose` and `blocks` of `{ kind: "narrative", text }`, `{ kind: "table", input: TableInput }`, `{ kind: "scatter", input: ScatterInput }` or `{ kind: "excerpts", input: ExcerptInput }`. Unknown kinds are rejected, and data never becomes raw HTML, CSS, JavaScript or a module path. This helper is intentionally bounded; it does not define the limits of the visual system.

For a genuinely new visual grammar, a report author can implement a new trusted TypeScript module in the report working directory, import library functions or write a browser-native renderer, and compile that module with the build tool's explicit `--entry`, `--root`, `--output` and `--global` options. Static local imports require no browser package loader. A custom renderer can return an HTML fragment or manipulate its own DOM; it is executable authoring code and requires the same review as the surrounding report scripts. Use `escapeText` for HTML text/attribute data or DOM `textContent`, validate numeric coordinates and links, retain exact accessible data and annotations, and do not interpolate untrusted markup. The packager's ability to embed a script is not a sandbox for that script and does not establish the correctness of its interpretation.

For example, a new task-specific relationship view can be implemented in `custom-view.ts`, using its own layout while returning an escaped figure plus an ordinary HTML relationship table. A figure generated outside TypeScript can be embedded through `nativeArtifactViewer` when raster output is suitable, or through the packager's reviewed static figure route. Do not flatten meaning into an existing score, table or plot merely to stay inside the standard catalog. A supplied static figure still needs source identity, units, uncertainty, notes, relevant evidence, an accessible explanation or table and visual verification. If a new interpretation is necessary, return that decision to the appropriate adjudication stage rather than concealing it in rendering code.

## Checks and practical limits

Renderer tests compile the real sources and synthetic demonstration, then check escaped data and rejected URL schemes, numeric geometry across finite extremes, close finite values and constant domains, actual narrow-domain ratios, distinct ticks and explicit offsets, missingness, interval markers, trajectory gaps, arbitrary row growth, supplied-only frontier connections, duplicate-label identity retention, graph boundary attachment and tangent-aligned arrowheads, signed heatmap values, calendar validation, native scenario controls, artifact restrictions and expanded-view annotations. Run `python3 -m unittest discover -s tests -p test_renderers.py -v` from this directory. The test runner needs Node.js and an installed TypeScript compiler; it installs nothing. Packaging checks cover a separate interface.

Structural and numeric checks do not establish a report's analytical fidelity, browser layout, assistive-technology experience or the quality of the underlying comparison. Inspect the actual standalone report offline, including narrow screens, long labels, larger datasets, keyboard navigation, missing inputs and every consequential supplied conclusion. Match visual aggregation, ordering, color, omitted cases and interaction to the approved evidence. A presentation defect belongs with the visual finalizer; a newly exposed substantive defect belongs with its decision owner.


### Qualification of this revision

The four maintained preview compositions cover a small conclusion, independently embedded themed reports, an extensive mixed-evidence example and a long-content stress composition. They are not a prescribed report architecture. The optional native test command is documented in [PACKAGING.md](PACKAGING.md); source and model checks remain useful but do not replace opening the final file in its intended reader environment. Keep point-in-time qualification evidence outside the shipped plugin.

The standalone assembler includes a small generated startup prelude before reader content. It waits for initial owned restoration before revealing an enhanced workspace, with a post-parse missing-enhancement deadline, a bounded claimed-restoration deadline and an error fallback (see PACKAGING.md). It never reads or writes records itself. Missing enhancement, blocked storage or slow restoration must not leave the evidence invisible; a late restoration after the limit can still visibly change the report. Theme changes are applied as one paint update, and unchanged persistence confirmations do not restart diagram rendering. This is a bounded flicker reduction, not a guarantee across all browser startup conditions.
