Harbor: the promised distribution is not self-contained

Harbor’s README says to copy only skills/harbor and promises that no other files are needed. Its entry point nevertheless requires ../policy/rules.md, which sits outside that directory. That omitted file carries consequential requirements: use only confirmed records, produce a draft, and do not send within this capability. See targets/harbor/README.md:1, skills/harbor/SKILL.md:7, and skills/policy/rules.md:3 in the original source excerpts.

This failure was reproduced at the declared distribution boundary. The supplied reference reporter passes against the original repository tree but reports missing_reference_file after copying only the promised skill directory. The skill copy itself is intact; the missing dependency is outside its payload. Validation evidence

The proposed replacement for Harbor’s body instruction is:

You SHALL prepare and return a draft dispatch note using only confirmed records from those supplied. You SHALL NOT send; sending is outside this capability.

This puts the complete, short policy into the standalone artifact without changing the installation promise or expanding the capability. It requires no additional files. The proposal leaves the original sibling policy file alone, but the skill no longer depends on it.

The demonstrated problem is missing required guidance, not observed unauthorized execution. A consumer might stop at the missing reference or proceed without those constraints; no model run established either outcome.

Juniper: its shared-resource arrangement is sound

Juniper uses the same relative reference, but its distribution contract is different. Its README explicitly requires the complete plugin, identifies the shared rules as a required public resource, and excludes standalone skill-folder installation. The complete-plugin copy preserves the rules file, and the reference resolves with its contents unchanged. See targets/juniper/README.md:1, skills/juniper/SKILL.md:7, and skills/policy/rules.md:3 in the source excerpts; the copy results are retained in the validation evidence.

No correction is warranted for this relationship. There is no reason to prohibit the sibling link, duplicate the rules, or require another skill invocation merely to read that public resource. Breaking an explicitly unsupported skill-only extraction would not invalidate Juniper’s supported complete-plugin distribution.

This is the important distinction between Harbor and Juniper: the same path can be valid or defective depending on what the consumer is promised and actually receives.

Cedar: repair navigation, not the pinned contract

Cedar’s entry point directs the reader to section 2 for sending authorization. The guide actually contains:

Section 1, “Sending authorization”: draft only; obtain explicit authorization before sending.

Section 2, “Formatting”: destination label first, dispatch text second.

The guide file exists, so a file-existence check passes. The defect is semantic: the specified section does not supply the requirement the entry point says it does. See targets/cedar/skills/cedar/SKILL.md:7 and references/guide.md:3–9 in the source excerpts.

The proposed replacement paragraph is:

You SHALL use section 1 ("Sending authorization") of the [guide](references/guide.md) for sending authorization. AtlasExport 1.2 requires the legacy export mode described in the supplied contract.

This corrects the route without granting standing permission to send. Cedar’s contract continues to require explicit user authorization; the review itself supplies none.

Retain AtlasExport 1.2, legacy, and the 2024-06-01 compatibility date. The README expressly excludes an upgrade, contract.json permits only legacy, and the guide explains that the date identifies a compatibility record—not a current-vendor release claim. There is no demonstrated staleness to repair. Substituting a hypothetical newer mode would contradict the supplied contract rather than improve compliance. See targets/cedar/README.md:1, contract.json:2–8, and references/guide.md:11–13 in the source excerpts.
