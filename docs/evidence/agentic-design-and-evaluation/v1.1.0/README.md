# Agentic Design & Evaluation 1.1.0 evidence

This revision clarifies public resource ownership and complete-plugin distribution, removes mirrored navigation and development anecdotes from runtime guidance, makes source-grounded reconstruction explicit, and corrects four reproduced reporter defects. The complete foundation remains available and the separate charter is unchanged. The source review and Pro consultation preceded implementation; the following task uses exercise the candidate against independently specified requests rather than ask it to certify itself.

## Mechanical evidence

The reporter suite passes 82 tests, including independent controls for Unicode differences versus equivalent JSON encodings, symlink retargeting versus unchanged links, control-character paths, equivalent pretty/minified catalogs, and failed collection. A further regression preserves the distinction between a regular file named `scripts` and the scripts directory. The package/wrapper/profile suite passes 14 tests, converter unit tests pass 29, installer tests pass 37, and explicitly enabled native CLI/profile checks pass six. These groups overlap in profile checks; their counts are not a count of unique independent observations.

The final package is round-tripped through both targets, and the converted outputs pass their target validators. Package tests use actual converter outputs, remove the temporary source checkout, independently follow the published resource links, and exercise command entry points from an unrelated working directory. They establish packaging and interface properties, not semantic quality or model behavior. The native CLI tests use a positively identified temporary profile for Codex and Claude's strict validator; they do not run native models.

The ancillary Skill Creator helper rejects `compatibility` because that field is absent from its local whitelist. The field is part of the portable Agent Skills specification and is required by this revision's declared dependency contract. The helper's results are retained in `observations/mechanical-summary.json`; they are not treated as a reason to erase valid metadata or as proof of a host rejection.

## Behavioral evidence

The contexts were fresh temporary ChatGPT chats with Personalized enabled and the visible `6 Pro` selection; Latest was verified in the selector. Personalized temporary chats can reference plugins and custom instructions. Exact backend identity, complete ambient isolation, native Codex/Claude behavior, and implicit-selection reliability are not established. The audit/comparison and comparison/handoff cases overlapped in separate tabs; no timing comparison is inferred.

All responses were identified and read after active generation ended on two checks separated by a settle wait. Rendered response transcriptions preserve substantive text with citation wrapping and table delimiters normalized where stated. Downloaded artifact payloads are preserved: the continuation's exact native text and hash are in `responses/missing.json`, while its readable Markdown copy normalizes the final blank line. These captures and authored logs are not independently authenticated historical tool-execution traces.

## Revision identity and retained material

`cases/` contains the original synthetic requests and materials. `responses/` contains the completed response transcriptions, capture metadata, the comparison log, and the native continuation artifact. `observations/` contains independently obtained facts, source identities, and the task-specific acceptance conditions.

The frozen browser candidate contains 41 files. After freezing it, the script collector received the regular-file-named-`scripts` correction and its regression. All instruction and UI-metadata files supplied to the trials are identical to the release; the changed collector condition is not exercised by those task inputs. `post-freeze-correction.json` identifies the two changed code/test files, and the final mechanical checks cover the corrected source. Earlier observations are not relabeled as runs of every final code byte.

The complete frozen packet and private installation inventories remain in the local task record. They are not runtime dependencies. Publication, actual selected installation, fresh native catalog exposure, and preservation of unrelated host state require their own delivery record; conversion and browser task success alone do not establish those effects.
