## Selected installation and recovery

The published package passed GitHub CI and was installed from the canonical GitHub marketplace in both CLIs. All 38 source files matched both installed caches. Retirement removed the two old Codex namespaces; the old Claude registrations and enablement keys were retired while their inactive cache payloads were retained. Fresh Codex prompt input exposed all four new entries and neither obsolete plugin namespace. This remains input/exposure evidence, not a native model execution.

The first selected install failed because the configured Git marketplace snapshot did not contain the new name. The installer had refreshed snapshots for updates but not for additions. Its refresh condition now covers both, with an ordering regression on both host interfaces.

A later check during the multi-host migration found that Claude's installed registry contained only the new entry, although the saved pre-migration CLI inventory contained 21 installations. Existing caches and enablement settings remained present. Nineteen unrelated registrations were reconstructed from that saved inventory, preserving the exposed versions, scopes, cache paths, and installation timestamps; unrelated enablement and other settings were preserved. Full prior registry bytes were not captured, so exact preservation of unexposed optional metadata is not claimed. Subsequent verification matched all 24 unrelated Codex installations and all 19 unrelated Claude installations against the saved inventory.

The exact originating operation for that registry loss was not established. A separate, positively identified disposable Claude profile preserved its unrelated marker during a native install, so that probe did not reproduce the loss. The installer now snapshots the native version-2 registry before the selected multi-host transaction and preserves missing non-selected entries with their complete raw metadata. Controlled overwrite, failed-call, conflicting-change, unreadable-state, and unsupported-format cases test that protection; the native probe separately confirms ordinary integration. This is a response to an observed state-preservation failure, not a claim that every Claude installation loses data or that profile selection proves complete isolation.

The follow-up review identified and corrected transaction activation and installation-identity gaps: a Claude no-op no longer disables protection when Codex mutates, selected-but-unchanged Claude records remain protected, and the mutation exemption includes native project identity. Discovery, planning, receipts, and final verification distinguish user/project/local installations and the recorded project path. A disposable native probe on Claude Code 2.1.270 established that both project and local registrations used the nested process working directory as `projectPath`; the local settings file was written at the containing Git root, demonstrating why those two paths must not be conflated. Process-level counterexamples cover mixed-host no-ops, both-mutating controls, unsupported pre-state, dry runs, two projects sharing a scope, and wrong-scope success.
